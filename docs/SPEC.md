# สเปกระบบบริหารงานสถานฟื้นฟูสมรรถภาพผู้ติดยาเสพติด (เรือนจำ)

เอกสารนี้คือข้อกำหนดทั้งหมดของระบบ ให้ Claude Code อ่านก่อนเริ่มงานทุกครั้ง
ทำงานทีละขั้นตามหัวข้อ 23 "แผนการพัฒนา" เท่านั้น อย่าสร้างทุกอย่างพร้อมกัน
ถ้าข้อใดไม่ชัดเจนหรือขัดกัน ให้ถามเจ้าของโครงการก่อนเดาเอง

---

## 0. บริบทและหลักการ

### 0.1 บริบท
- ผู้ใช้: เจ้าหน้าที่สถานฟื้นฟูในเรือนจำ 6–8 คน + เจ้าหน้าที่สถานพยาบาล + การเงิน + ผู้บริหาร
  ส่วนใหญ่ไม่ถนัดคอมพิวเตอร์ บางคนใช้นานๆ ครั้ง
- ปริมาณ: ประมาณ 500 คนต่อปีงบประมาณ (12 วัน ~300 คน, 3 วัน ~100 คน, ชุมชนบำบัด + อื่นๆ)
  ใช้งานพร้อมกันไม่เกิน 10 คน
- หลักสูตร 3 หลักสูตร (เพิ่มได้ในอนาคต):
  1) ปรับเปลี่ยนพฤติกรรม 12 วัน (60 ชม.)
  2) ชุมชนบำบัด FAST Model 6 เดือน (24 สัปดาห์)
  3) ฟื้นฟูสมรรถภาพก่อนพ้นโทษ 3 วัน (15 ชม.)
- 1 หลักสูตร 1 ปีงบประมาณ มีหลายรุ่น (ปกติ 2–3 รุ่น)
- ภาษาไทยทั้งระบบ วันที่แสดงเป็น พ.ศ. ปีงบประมาณ 1 ต.ค. – 30 ก.ย.

### 0.2 หลักการสูงสุด (เรียงตามความสำคัญ)
1. **ความปลอดภัยของข้อมูล** — ข้อมูลอ่อนไหวสูง: ผู้ต้องขัง + ผู้ติดยาเสพติด + ข้อมูลสุขภาพ
2. **ข้อมูลไม่หาย** — สำรองข้อมูลเชื่อถือได้ กู้คืนได้จริง
3. **ใช้ง่าย** — คนใหม่ใช้ได้ภายใน 10 นาทีโดยไม่ต้องอบรม
4. **ดูแลง่าย** — เจ้าของโครงการไม่ใช่โปรแกรมเมอร์ เลือกเทคโนโลยีที่เรียบง่ายที่สุดเสมอ
5. ฟีเจอร์ใหม่ต้องไม่ขัดกับข้อ 1–4 ถ้าขัดให้ถามก่อน

### 0.3 กฎเหล็กระหว่างการพัฒนา
- **ห้ามใช้ข้อมูลผู้ต้องขังจริงระหว่างพัฒนาโดยเด็ดขาด** ใช้ข้อมูลปลอมจาก seed script เท่านั้น
  ห้ามเปิดอ่านไฟล์ฐานข้อมูลจริง ไฟล์สำรอง หรือ Excel รายชื่อจริง ถ้าพบไฟล์ลักษณะนี้ในโฟลเดอร์ให้หยุดและแจ้งเจ้าของ
- ใช้ Git ทุกขั้น commit บ่อยๆ พร้อมข้อความภาษาไทยที่เข้าใจง่าย
- `.gitignore` ต้องกันโฟลเดอร์ข้อมูล ไฟล์ฐานข้อมูล ไฟล์สำรอง ไฟล์ .env ไม่ให้เข้า Git
- จบแต่ละขั้น: สรุปเป็นภาษาไทยว่าทำอะไรไป ทดสอบอย่างไร และให้รายการงานทดสอบสำหรับเจ้าหน้าที่แต่ละบทบาท

## 1. เทคโนโลยีและการติดตั้ง

- Next.js (App Router) + TypeScript + Tailwind CSS
- **SQLite** ผ่าน Prisma (หรือ Drizzle) — ฐานข้อมูลเป็นไฟล์เดียว สำรอง/ย้ายเครื่องง่าย
  - เปิด WAL mode และตั้ง busy_timeout (เช่น 5000 ms) รองรับหลายคนใช้พร้อมกัน
  - ใช้ migration ทุกครั้งที่เปลี่ยนโครงสร้าง ห้ามแก้ฐานข้อมูลด้วยมือ
- **ไม่ใช้ Docker** รันด้วย Node.js ตรงๆ เป็น Windows Service (เช่น node-windows หรือ NSSM)
  เปิดเองอัตโนมัติเมื่อเปิดเครื่อง
- เครื่องแม่ข่าย Windows 10/11 ในหน่วยงาน, RAM 8 GB+, SSD 256 GB+, UPS
- ใช้งานผ่านเบราว์เซอร์จากเครื่องอื่นใน LAN ด้วย HTTPS (ใบรับรองของหน่วยงานเอง เช่น mkcert)
- ฮาร์ดดิสก์ภายนอกเสียบไว้ตลอด สำหรับไฟล์สำรอง (ตั้งค่าตำแหน่งได้)
- มีสภาพแวดล้อมทดสอบ (โฟลเดอร์/ฐานข้อมูลแยก) สำหรับลองอัปเดตก่อนใช้จริง
- **พัฒนาที่บ้าน → ติดตั้งใช้จริงที่ทำงาน**:
  - เครื่องที่บ้านมีแต่ข้อมูลปลอม (seed) เครื่องที่ทำงานมีข้อมูลจริง ห้ามย้ายข้อมูลข้ามกันทั้งสองทาง
  - ย้ายเฉพาะโค้ดผ่าน GitHub (repository แบบ Private) หรือ USB
  - สคริปต์ `install.ps1` (Windows): ตรวจ/ติดตั้ง Node.js, ติดตั้ง package, สร้างฐานข้อมูลว่าง,
    สร้าง .env (ถามค่าที่จำเป็นทีละข้อเป็นภาษาไทย), ตั้ง HTTPS, ติดตั้ง Windows Service,
    สร้างบัญชีหัวหน้าคนแรก — ทำงานได้ในคำสั่งเดียว
  - สคริปต์ `update.ps1`: สำรองข้อมูล → ดึงโค้ดใหม่ → migration → รีสตาร์ท → ถ้าพังย้อนกลับเวอร์ชันเดิม
  - ถ้าเครื่องที่ทำงานไม่มีอินเทอร์เน็ต: ทำ "ชุดติดตั้งออฟไลน์" (zip รวม package ทั้งหมด
    สำหรับ Windows x64) ไปทาง USB — package ที่ต้องคอมไพล์ (เช่น SQLite, argon2) ต้องเป็นของ Windows
  - README ส่วน "ติดตั้งที่ทำงานครั้งแรก" ทีละขั้นพร้อมภาพประกอบ
- README ภาษาไทยสำหรับคนไม่ใช่โปรแกรมเมอร์: ติดตั้ง, อัปเดต, สำรอง, กู้คืน, ย้ายเครื่อง,
  เปลี่ยนฮาร์ดดิสก์, ตั้งค่า LINE, แก้ปัญหาเบื้องต้น

## 2. ความปลอดภัย

### 2.1 การเข้าสู่ระบบ (2 ชั้น)
- ชั้นที่ 1: รหัสหน่วยงาน (รหัสกลาง) → เครื่องที่ผ่านแล้วจำไว้ 30 วัน
- ชั้นที่ 2: หน้าแสดงการ์ดชื่อเจ้าหน้าที่พร้อมรูป/ตัวอักษรย่อ → กดชื่อตัวเอง → ใส่รหัสผ่านประจำตัว
- ปุ่ม "สลับผู้ใช้" มุมบนขวา กลับหน้าเลือกชื่อโดยไม่ต้องใส่รหัสหน่วยงานใหม่
- รหัสผ่าน ≥ 8 ตัว เก็บแบบ hash (Argon2 หรือ bcrypt) ห้ามรหัสง่ายเกินไป
- บังคับเปลี่ยนรหัสเมื่อเข้าครั้งแรก, ผู้ดูแลรีเซ็ตให้ได้
- ผิด 5 ครั้ง ล็อก 15 นาที, แจ้งผู้ดูแลเมื่อผิดผิดปกติ
- ออกจากระบบอัตโนมัติเมื่อไม่ใช้ 15 นาที (เตือนก่อน 1 นาที)
- ผู้ดูแลระบบไม่เกิน 2 คน — **ไม่ใช้ OTP เป็นค่าเริ่มต้น** (ในเรือนจำห้าม/ไม่สะดวกนำมือถือเข้า)
  ชดเชยด้วย: รหัสผ่านผู้ดูแลอย่างน้อย 12 ตัว, การกระทำสำคัญยังต้องยืนยัน 2 คน (หัวหน้า+รอง),
  แจ้งเตือนอีกคนเมื่อผู้ดูแลเข้าระบบนอกเวลาราชการ
  OTP เก็บเป็นตัวเลือกเปิดได้ในตั้งค่า (เผื่ออนาคต) ปิดไว้ก่อน
- ระงับบัญชีได้ทันที (ไม่ลบ เพื่อเก็บประวัติ)

### 2.2 บทบาทและสิทธิ์ (ให้น้อยที่สุดเท่าที่จำเป็น)
- ผู้ดูแลระบบ / เจ้าหน้าที่ฟื้นฟู / เจ้าหน้าที่สถานพยาบาล / การเงิน / ผู้บริหาร (ดูอย่างเดียว)
- ตรวจสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ทุกคำขอ (ไม่ใช่แค่ซ่อนปุ่ม)
- เมนูที่ไม่มีสิทธิ์ให้ซ่อนไปเลย
- ข้อมูลสุขภาพ (PMHQ, 2Q/9Q/8Q, SCL-90-R, ความเห็นแพทย์, ข้อมูลส่งต่อสุขภาพ)
  เห็นเฉพาะสถานพยาบาลและผู้ดูแล
- เลขบัตรประชาชนแสดงแบบปิดบัง (x-xxxx-xxxxx-12-3) กดดูเต็มได้เฉพาะผู้มีสิทธิ์ และบันทึกการกดดู
- ส่งออก Excel ที่มีชื่อผู้ต้องขัง: เฉพาะผู้มีสิทธิ์
- เอกสารที่พิมพ์ทุกฉบับมีท้ายกระดาษ "พิมพ์โดย ... วันเวลา ..."

### 2.2-0 โครงสร้างบุคลากรของหน่วยงาน (เรือนจำกลางเชียงใหม่)
**ระดับบริหาร** (บทบาท "ผู้บริหาร" — ดูอย่างเดียว ไม่มีปุ่มแก้ไข)
1. ผู้บัญชาการเรือนจำกลางเชียงใหม่ — ผู้อนุมัติสูงสุดในเอกสาร, "เรียน" ในหนังสือ/แบบ KTB
2. ผู้อำนวยการสถานพยาบาล — ผู้บังคับบัญชาสายตรงของสถานฟื้นฟู, ดูอย่างเดียว
   (ไม่มีหน้าที่อนุมัติในระบบ) ดูสรุปข้อมูลสุขภาพแบบไม่ระบุชื่อได้

**ผู้ปฏิบัติหลัก** (บทบาท "ผู้ดูแลระบบ")
3. หัวหน้าสถานฟื้นฟูสมรรถภาพผู้ติดยาเสพติด (เจ้าของโครงการ)
4. รองหัวหน้า

**เจ้าหน้าที่สถานฟื้นฟู** แยก 3 กลุ่มตามบทบาทจริงในงาน — วิชาชีพกำหนดสิทธิ์เริ่มต้น

กลุ่ม A **ผู้ดูแลหลักประจำ** (บทบาท "เจ้าหน้าที่หลัก") — ใช้ระบบทุกวัน ทำงานเกือบทุกส่วน
| วิชาชีพ | สิทธิ์ |
|---|---|
| พยาบาลวิชาชีพ | งานฟื้นฟูทั้งหมด (ทะเบียน เช็คชื่อ แบบประเมินทุกชนิด ชุมชนบำบัด สมุดส่วนที่ 3–4 บสต./รท.101 ติดตาม ออกจากเรือนจำ ครอบครัว) + **ข้อมูลสุขภาพทั้งหมด** (สภาวะกาย/จิต PMHQ 2Q 9Q 8Q โรคจิต ความเห็นสถานพยาบาล ส่งต่อสุขภาพ) |
| นักจิตวิทยา | งานฟื้นฟูทั้งหมดเหมือนพยาบาล + **ข้อมูลสุขภาพจิต** (PMHQ 2Q 9Q 8Q โรคจิต SCL-90-R Rosenberg ความเห็นด้านจิตวิทยา) — ข้อมูลสุขภาพกายดูได้ |
- หน้าแรกของกลุ่มนี้เป็นหน้าจอเต็ม (งานของฉันวันนี้ ครบทุกการ์ด)

กลุ่ม B **ผู้ช่วยเป็นครั้งคราว** (บทบาท "ผู้ช่วย") — มาช่วยบางครั้ง บางช่วงไม่มาเลย
| วิชาชีพ | สิทธิ์ |
|---|---|
| นักฝึกอบรมวิชาชีพ | ดูตารางของตน, เช็คชื่อคาบที่ตนสอน, บันทึก "สอนแล้ว"/ผลกิจกรรม, ทีมงาน/งานบำบัดเมื่อได้รับมอบหมาย |
| นักสังคมสงเคราะห์ | ดูตารางของตน, เช็คชื่อคาบที่ตนสอน, บันทึก "สอนแล้ว"/ผลกิจกรรม, ข้อมูลครอบครัว/ผู้ติดต่อและติดตามหลังบำบัดเมื่อได้รับมอบหมาย |
- หน้าแรกแบบเรียบง่าย: "คาบของฉันวันนี้" + ปุ่มเช็คชื่อ + ปุ่มบันทึกผล เท่านั้น
- ไม่เห็นข้อมูลสุขภาพ, เห็นรายชื่อเฉพาะรุ่นที่ตนสอน
- บัญชีที่ไม่ได้ใช้เกิน 60 วัน ระบบเตือนหัวหน้า/รองให้ทบทวน (ระงับได้)

กลุ่ม C **ผู้ควบคุม** (เจ้าหน้าที่ราชทัณฑ์/ผู้คุม) — ควบคุมความปลอดภัยเท่านั้น
- ค่าเริ่มต้น: **ไม่มีบัญชี** ไม่เข้าระบบ
- ถ้าจำเป็น หัวหน้า/รองเปิดบัญชีแบบ "ดูอย่างเดียว" ได้: เห็นตารางกิจกรรมวันนี้ + รายชื่อและรูป
  ผู้เข้ารับการฟื้นฟู (สำหรับนับยอด) — ไม่เห็นคดีละเอียด ไม่เห็นข้อมูลสุขภาพ ไม่เห็นผลประเมิน
- พิมพ์ "ใบรายชื่อนับยอดประจำวัน" (ชื่อ เลขประจำตัว รูป แดน กิจกรรม) ให้ผู้คุมได้โดยไม่ต้องมีบัญชี

- หัวหน้า/รองปรับสิทธิ์รายคนได้ (เพิ่ม/ลด/ย้ายกลุ่ม) และมอบหมายงานเฉพาะให้กลุ่ม B เป็นรายรุ่น
- ข้อมูลบุคลากรเก็บ: ชื่อ ตำแหน่ง วิชาชีพ ระดับ (บริหาร/ผู้ปฏิบัติหลัก/เจ้าหน้าที่) — ใช้เติมเอกสารด้วย

**สายลงนามในเอกสาร (ค่าเริ่มต้น แก้ได้ในตั้งค่า)**
- ผู้จัดทำ: ผู้รับผิดชอบ/เจ้าหน้าที่ → ผู้ตรวจสอบ: หัวหน้าหรือรองหัวหน้า →
  ผู้เห็นชอบ: ผู้อำนวยการสถานพยาบาล → ผู้อนุมัติ: ผู้บัญชาการเรือนจำกลางเชียงใหม่
- ชื่อและตำแหน่งดึงจากข้อมูลบุคลากรปัจจุบัน (เปลี่ยนตัวผู้บริหารแก้ที่เดียว เอกสารใหม่เปลี่ยนตาม
  เอกสารที่พิมพ์ไปแล้วคงชื่อเดิม)
- รายงานประจำสัปดาห์และแดชบอร์ดส่งถึงผู้บริหารทั้ง 2 ท่าน

### 2.2A ตารางสิทธิ์ตามบทบาท (ค่าเริ่มต้น — ผู้ดูแลปรับรายคนได้ผ่านหน้า "สิทธิ์ผู้ใช้")
ความหมาย: แก้ = เพิ่ม/แก้/ลบ, ดู = ดูอย่างเดียว, ของตน = เฉพาะที่ตัวเองรับผิดชอบ, — = มองไม่เห็นเมนู
คอลัมน์: ผู้ดูแล = หัวหน้า/รอง, ฟื้นฟู = งานฟื้นฟูของกลุ่ม A (พยาบาล/นักจิตวิทยา),

หลักการเพิ่มเติม:
- **ขอเปลี่ยนตาราง**: เจ้าหน้าที่ที่ไม่ใช่ผู้ดูแล กด "ขอเปลี่ยน/ขอสลับคาบ" พร้อมเหตุผล
  → แจ้งผู้ดูแล → อนุมัติ/ไม่อนุมัติ (ผู้ดูแลไม่ต้องคอยรับเรื่องปากเปล่า)
- **ล็อกค่าตอบแทนเป็นขั้น**: ร่าง → ผู้ดูแล "อนุมัติ" → ล็อก (แก้ตาราง/สอนจริงของช่วงนั้นไม่ได้)
  → การเงินพิมพ์/ติ๊กเซ็นรับ → "เบิกจ่ายแล้ว" ปลดล็อกได้เฉพาะผู้ดูแลพร้อมเหตุผล (บันทึก audit)
- **ผู้ดูแลระบบ 2 คน**: หัวหน้าสถานฟื้นฟู (เจ้าของโครงการ) และรองหัวหน้า — สิทธิ์เท่ากัน
  หน้าจอแสดงตำแหน่ง "หัวหน้า" / "รองหัวหน้า" ชัดเจน
- **แยกหน้าที่**: ผู้ที่เป็นวิทยากรในคาบนั้นจะอนุมัติค่าตอบแทนของตัวเองไม่ได้
  → ค่าตอบแทนของหัวหน้า ให้รองหัวหน้าอนุมัติ / ของรองหัวหน้า ให้หัวหน้าอนุมัติ (ระบบสลับให้อัตโนมัติ)
  → ไม่มีผู้อนุมัติสำรองนอกจากหัวหน้า/รอง ถ้าอีกคนไม่อยู่ รายการรออนุมัติค้างไว้ในคิว
    แจ้งเตือนเมื่อกลับมา (ผู้บริหารดูได้อย่างเดียว ไม่อนุมัติในระบบ)
- **การกระทำสำคัญต้องยืนยัน 2 คน** (หัวหน้า + รอง): กู้คืนข้อมูลจากไฟล์สำรอง, ลบข้อมูลถาวร,
  ปลดล็อกค่าตอบแทนที่เบิกจ่ายแล้ว, เปลี่ยนสิทธิ์ผู้ดูแล — คนหนึ่งขอ อีกคนกดยืนยัน
- **กรณีฉุกเฉิน** (อีกคนไม่อยู่นาน): README มีขั้นตอนใช้ "รหัสฉุกเฉิน" ที่พิมพ์ใส่ซองปิดผนึกเก็บไว้
  ใช้แล้วต้องเปลี่ยนรหัสใหม่ และบันทึก audit log
- **มอบสิทธิ์ชั่วคราว**: ผู้ดูแลมอบสิทธิ์จัดตารางให้เจ้าหน้าที่บางคนได้ เป็นช่วงวันที่ (เช่น ตอนลา)
  หมดเวลาแล้วสิทธิ์กลับอัตโนมัติ
- ผู้ใช้ 1 คนมีได้หลายบทบาท (เช่น พยาบาลที่เป็นวิทยากรด้วย) สิทธิ์รวมกัน
- การเปลี่ยนสิทธิ์ทุกครั้งบันทึก audit log

### 2.3 การเข้ารหัส
- HTTPS ภายใน LAN
- README: วิธีเปิด BitLocker ทั้งดิสก์เครื่องแม่ข่ายและฮาร์ดดิสก์สำรอง

### 2.4 ประวัติการใช้งาน (Audit log)
- บันทึก: เข้า/ออกระบบ (สำเร็จ/ไม่สำเร็จ), เพิ่ม/แก้/ลบ (ค่าเดิม→ค่าใหม่),
  เปิดดูข้อมูลอ่อนไหว, พิมพ์, ส่งออก, สำรอง/กู้คืน, เปลี่ยนสิทธิ์ — ผู้ใช้ เวลา IP
- ตาราง audit แบบเพิ่มได้อย่างเดียว ไม่มีหน้าจอแก้/ลบ แม้แต่ผู้ดูแล
- แจ้งเตือนผู้ดูแลเมื่อผิดปกติ: ส่งออกจำนวนมาก, เปิดดูข้อมูลสุขภาพหลายคนติดกัน, เข้านอกเวลาราชการ
- ทุกรายการข้อมูลแสดง "บันทึกโดย ... เมื่อ ..." และ "แก้ไขล่าสุดโดย ... เมื่อ ..."
- ลบข้อมูลแบบซ่อน (soft delete) กู้คืนได้ ลบถาวรเฉพาะผู้ดูแลพร้อมเหตุผล
- หน้าผู้ดูแลค้นหาประวัติตามผู้ใช้ / ผู้ต้องขัง / ช่วงวันที่

### 2.5 เครือข่าย
- เข้าระบบได้เฉพาะใน LAN ห้ามเปิดพอร์ตรับจากอินเทอร์เน็ต ไม่มี remote access
- ขาออกอนุญาตเฉพาะ api.line.me (README ระบุให้ฝ่าย IT ตั้ง firewall)
- ข้อความ LINE ห้ามมีข้อมูลผู้ต้องขังทุกกรณี

### 2.6 การทดสอบความปลอดภัย (ทุกขั้นก่อนส่งมอบ)
- เข้าหน้าใดๆ โดยไม่ล็อกอินไม่ได้
- บทบาทหนึ่งเข้าข้อมูลของอีกบทบาทไม่ได้ (ลองเปลี่ยน URL/ID ตรงๆ)
- ป้องกัน SQL injection, XSS, CSRF
- ส่งรายงานผลการตรวจเป็นภาษาไทย

### 2.7 ความปลอดภัยทางกายภาพและการปฏิบัติ (เช็คลิสต์ใน README)
- เครื่องแม่ข่ายในห้องล็อก + UPS ปิดเครื่องปลอดภัยเมื่อไฟดับนาน

- PDPA: ระยะเวลาเก็บข้อมูลและการทำลายเมื่อพ้นระยะ (ตั้งค่าได้)
- ขั้นตอนเมื่อสงสัยว่าข้อมูลรั่ว

## 3. การสำรองข้อมูล (หลัก 3-2-1)

- ใช้ SQLite online backup API (ห้ามคัดลอกไฟล์ขณะเขียน) แล้วบีบอัด + เข้ารหัส AES-256
- อัตโนมัติทุก 4 ชั่วโมงในเวลาราชการ + ทุกคืน 22.00 น.
- เก็บ: รายวัน 30 วัน / รายสัปดาห์ 12 / รายเดือน 12 / รายปีเก็บตลอด
- ชุดที่ 1: ดิสก์ในเครื่อง / ชุดที่ 2: ฮาร์ดดิสก์ภายนอกที่เสียบไว้ /
  ชุดที่ 3: ฮาร์ดดิสก์ลูกที่ 2 แบบถอดเก็บ (ปุ่ม "สำรองลงฮาร์ดดิสก์ถอดเก็บ") เตือนถ้าเกิน 30 วัน
- ตรวจ checksum หลังสำรองทุกครั้ง
- ทดสอบกู้คืนอัตโนมัติทุกสัปดาห์ (กู้ลงฐานทดสอบ นับจำนวนข้อมูลเทียบ) แจ้งผลในหน้าผู้ดูแล
- สำรองอัตโนมัติก่อนอัปเดตโปรแกรมและก่อนกู้คืนทุกครั้ง
- ตรวจฮาร์ดดิสก์ภายนอกทุก 5 นาที หลุด → แถบแดงหน้าผู้ดูแล, เสียบกลับทำงานต่อเอง
- ล้มเหลว → แถบแดง + แจ้งผู้ดูแลทาง LINE (ไม่มีข้อมูลผู้ต้องขัง)
- หน้าสถานะ: สำรองล่าสุด, ทดสอบกู้คืนล่าสุด, ดิสก์เชื่อมต่อไหม, พื้นที่คงเหลือ (เตือนเกิน 80%)
- หน้ากู้คืน: เลือกจากวันที่ → ยืนยัน 2 ชั้น → สำรองข้อมูลปัจจุบันก่อนกู้เสมอ

## 4. การออกแบบให้ใช้ง่ายสำหรับผู้ใช้หลายคน

### 4.1 โครงหน้าจอหลัก
เข้าระบบ → **เลือกหลักสูตร** → **เลือกรุ่น** → **หน้ารุ่น**
- หน้าเลือกหลักสูตร: การ์ดใหญ่ แสดงจำนวนรุ่นที่ดำเนินการและจำนวนคนตอนนี้
- หน้าเลือกรุ่น: ตัวเลือกปีงบด้านบน (ค่าเริ่มต้นปีปัจจุบัน), การ์ดรุ่น "รุ่นที่ 1/2569"
  วันเริ่ม–สิ้นสุด จำนวนคน สถานะ แถบความคืบหน้า, ปุ่ม "+ สร้างรุ่นใหม่",
  ปุ่ม "สรุปทั้งหลักสูตรปีนี้"
- หน้ารุ่น: แท็บ ภาพรวม | รายชื่อ | เช็คชื่อ | ตารางกิจกรรม | แบบประเมิน |
  สถานพยาบาล | ชุมชนบำบัด (เฉพาะ 6 เดือน) | ค่าตอบแทน | งบประมาณ | รายงาน
- แท็บภาพรวม: วันนี้วันที่เท่าไรของหลักสูตร, กิจกรรมวันนี้, ยังไม่เช็คชื่อ, แจ้งเตือนของรุ่น
- Breadcrumb "หลักสูตร > ปีงบ > รุ่น" ตลอด, จำรุ่นล่าสุดที่ใช้
- เมนูกลาง (ข้ามหลักสูตร): ค้นหาบุคคล, งาน บสต./รท.101, บันทึกออกจากเรือนจำ,
  วิทยากรและค่าตอบแทน, งบประมาณ, รายงานภาพรวม, ตั้งค่า (ผู้ดูแล)

### 4.2 หน้าแรก "งานของฉันวันนี้" ตามบทบาท
- ฟื้นฟู: เช็คชื่อที่ยังไม่ทำ, ตารางสอนของฉันวันนี้/พรุ่งนี้, ผลกิจกรรมที่ยังไม่บันทึก,
  Shot down/LE ครบกำหนด, แบบประเมินถึงรอบ
- สถานพยาบาล: ผู้ผลคัดกรองเสี่ยง, ความเห็นรอบันทึก, รายการส่งต่อสุขภาพ
- ผู้ลง บสต.: ค้างลง / ครบกำหนด / เลยกำหนด; รท.101: จำนวนผู้จบที่ยังไม่ลง
- การเงิน: ค่าตอบแทนรอสรุป, งบคงเหลือ
- ผู้บริหาร: แดชบอร์ด (ไม่มีปุ่มแก้ไข)

- ปฏิทินเลือกวันที่แบบ พ.ศ.

### 4.3A ข้อความบนหน้าจอ (Microcopy) — ต้องดูเป็นระบบงานราชการมืออาชีพ
- สั้น เป็นทางการ สุภาพ ใช้คำแบบระบบสารสนเทศหน่วยงานรัฐ ไม่เขียนแบบพูดคุย
- ห้ามบอกขั้นตอนภายใน/ใครเป็นคนให้รหัส บนหน้าจอ (เช่น "ถามหัวหน้าหรือรองหัวหน้า", "ขั้นที่ 1 จาก 2 — ...")
  ขั้นตอนแสดงด้วยจุดเล็ก ● ○ แทนข้อความ
- คำอธิบาย/วิธีใช้ไปอยู่ในปุ่ม (?) และคู่มือ ไม่แปะบนฟอร์ม
- ข้อความผิดพลาดสั้นและบอกสิ่งที่ต้องทำ: "รหัสหน่วยงานไม่ถูกต้อง", "บัญชีถูกระงับชั่วคราว 15 นาที"
- ภาษาอังกฤษใช้เฉพาะคำบรรยายรอง (tagline) ไม่ใช้ในปุ่ม/ป้าย
- หน้าเข้าระบบ:
  หัวเรื่อง "เข้าสู่ระบบ" / ช่อง "รหัสหน่วยงาน" / ☐ "จดจำเครื่องนี้ 30 วัน" / ปุ่ม "ถัดไป"
  ท้ายหน้าตัวเล็ก: "ระบบสารสนเทศสถานฟื้นฟูสมรรถภาพผู้ติดยาเสพติด เรือนจำกลางเชียงใหม่
  · สำหรับเจ้าหน้าที่ที่ได้รับอนุญาตเท่านั้น · การเข้าใช้งานทุกครั้งถูกบันทึก"
- ป้าย "ข้อมูลตัวอย่าง (ข้อมูลปลอม)" แสดงเฉพาะเครื่องทดสอบ (ซ่อนอัตโนมัติบนเครื่องใช้งานจริง)
- ตรวจข้อความทั้งระบบตามหลักนี้ก่อนปิดแต่ละขั้น

### 4.4 แนวทางหน้าตา (Visual design)

- รูปภาพ: กรอบทรงวงรี/แคปซูล หรือมุมโค้งใหญ่; รูปการ์ดหลักสูตรใช้โทน duotone เขียวมะนาว (เหมือนการ์ด Treatment Programs)

- หัวเรื่อง: ฟอนต์เรขาคณิตหนักแน่น — **IBM Plex Sans Thai** (หรือ Noto Sans Thai) ตัวหนา
  ตัวเลข/อังกฤษใช้ Space Grotesk ได้ / เนื้อหาใช้ Sarabun ≥ 16px (ฟอนต์ฝังในโปรเจกต์ ไม่โหลดจากเน็ต)

**นำรูปแบบในภาพมาใช้กับหน้าจอใดบ้าง**
- หน้าเข้าระบบชั้นที่ 1: พื้นไล่เฉดมะนาว→ครีม หัวเรื่องใหญ่กลางจอ (ชื่อศูนย์) ภาพธรรมชาติกรอบโค้ง 2–4 ภาพ
- หน้าเลือกผู้ใช้ (ชั้นที่ 2): การ์ดบุคลากรแบบ "Our Team" — รูปขาวดำบนพื้น periwinkle
  มีรูปทรงตกแต่งสีมะนาวด้านหลัง ป้ายชื่อ+วิชาชีพในแคปซูลขาวด้านล่าง
- หน้าเลือกหลักสูตร: การ์ด 3 ใบแบบ "Treatment Programs" บนพื้น navy — ชื่อหลักสูตร
  ภาพ duotone ทรงแคปซูล จำนวนรุ่น/คนตอนนี้
- ระยะการบำบัด (FAST 5 ระยะ) และขั้นตอนโครงการ 7 ขั้น (3 วัน): แบบ "How It Works"
  เลข 01–05 + ชื่อขั้น + คำอธิบาย แถบแคปซูลมะนาวจางเป็นแถบความคืบหน้า
- แดชบอร์ด/ภาพรวมรุ่น: ตัวเลขสถิติใหญ่แบบ "About Us" (คนในรุ่น % เข้าร่วม จบหลักสูตร งาน บสต. ค้าง)
- รายการ (กล่องจดหมายเวร, บันทึกพฤติกรรม): การ์ดยาวมุมโค้งแบบรายการบทความ มีแท็กแคปซูล + วันที่

**สิ่งที่ไม่นำมาใช้**
- แถบโลโก้วิ่ง, testimonial, ข้อความวิ่งพื้นดำ, จดหมายข่าว, ลิงก์โซเชียล (ไม่เหมาะกับเครื่องมือภายใน)
- รูปใบหน้าคนแสดงอาการซึมเศร้า/วิตกกังวล (ตีตรา ไม่เหมาะกับบริบทผู้ป่วย)
- **ห้ามใช้รูปจากภาพตัวอย่างโดยตรง** (มีลิขสิทธิ์) ใช้รูปฟรีตามข้อด้านล่างแทน
- หน้ากรอกข้อมูล เช็คชื่อ ตาราง: ไม่มีรูปตกแต่งและไม่มีมุมบาก — เรียบ เร็ว อ่านง่าย
- โทน: สงบ อบอุ่น ให้ความหวัง สะอาด ไม่ดูเป็นโรงพยาบาลหรือเรือนจำ
  การ์ดมุมโค้ง เงาบาง พื้นที่ว่างพอดี สีหลักโทนเขียว/ฟ้าอมเขียว + สีพื้นนวล
  กำหนดสีเป็นตัวแปรกลาง (design tokens) ที่เดียว ปรับทั้งระบบได้ง่าย
- สีสถานะ (เขียว/เหลือง/แดง) ต้องเด่นกว่าสีตกแต่งเสมอ
- รูปภาพตกแต่ง (หน้าเข้าระบบ, หน้าเลือกหลักสูตร, ภาพว่างเปล่าเมื่อไม่มีข้อมูล):
  ใช้ภาพฟรีที่อนุญาตใช้งาน (Unsplash, Pexels — ระบุแหล่งที่มาใน README)
  **ดาวน์โหลดมาเก็บในโปรเจกต์** (ระบบอยู่บน LAN ไม่มีอินเทอร์เน็ต) ย่อขนาดให้เล็ก
  เนื้อหาภาพ: ธรรมชาติ แสงเช้า มือประสาน ต้นไม้เติบโต — **ห้ามภาพคนในเรือนจำ ภาพยาเสพติด
  ภาพสื่อความรุนแรงหรือตีตรา** และห้ามใช้ภาพในหน้าที่ใช้กรอกข้อมูลจริง (รก ช้า)
- ไอคอนชุดเดียวทั้งระบบ (เช่น Lucide) มีข้อความกำกับ
- ฟอนต์หน้าจอ: Sarabun (หรือ Noto Sans Thai) / ฟอนต์เอกสารพิมพ์: TH Sarabun New

## 5. โครงสร้างข้อมูลหลัก (สำคัญที่สุด ออกแบบให้ถูกตั้งแต่แรก)

- **บุคคล (Person)**: คนจริง 1 คน อ้างอิงเลขบัตรประชาชน (ถ้ามี) — ชื่อ วันเกิด เพศ
- **การต้องโทษ (Incarceration)**: 1 ครั้งที่เข้าเรือนจำ อ้างอิง **เลขประจำตัวผู้ต้องขัง (unique)**
  - เลขนี้ไม่เปลี่ยนแม้ย้ายเรือนจำ เปลี่ยนเมื่อพ้นโทษแล้วกลับเข้ามาใหม่เท่านั้น
  - เก็บ: คดี กำหนดโทษ แดน/ห้อง ชั้นนักโทษ รูปถ่าย วันออกจากเรือนจำ + เหตุผล
- **การลงทะเบียนเข้ารุ่น (Enrollment)**: ผูกกับการต้องโทษ + รุ่น — วันเข้า วันออก สถานะ เหตุผล
- 1 บุคคล → หลายการต้องโทษ → แต่ละครั้งเข้าได้หลายหลักสูตร
- **หลักสูตร (Course)** → **ปีงบประมาณ** → **รุ่น (Cohort)**
- คลังที่ตั้งค่าได้: หัวข้อกิจกรรม, แบบประเมิน, อัตราค่าตอบแทน, หมวดงบ, เหตุผลต่างๆ,
  วันหยุดราชการ, ตำแหน่ง/ทีมงาน/เครื่องมือบ้าน
- ค่าที่ต้อง "แช่แข็ง" ณ เวลาที่เกิด: อัตราค่าตอบแทน ณ วันที่สอน, เกณฑ์แปลผล ณ วันที่ประเมิน
  (เปลี่ยนค่าตั้งปีใหม่ไม่กระทบข้อมูลเก่า)
- ทุกตารางมี created_by, created_at, updated_by, updated_at, deleted_at

## 6. หลักสูตรและรุ่น

- ตั้งค่ารายหลักสูตร: ระยะเวลา, ชั่วโมงรวม, เกณฑ์ % การเข้าร่วมที่ถือว่าผ่าน,
  ต้องลง บสต. / ต้องลง รท.101 / ต้องติดตามหลังบำบัด (เปิด/ปิด แยกกัน)
  - 12 วัน: บสต. + รท.101 + ติดตาม / 6 เดือน: บสต. + รท.101 + ติดตาม / 3 วัน: รท.101 เท่านั้น (ไม่ลง บสต. ไม่ติดตาม)
- สร้างรุ่น: เลขรุ่น + วันเริ่ม → คำนวณวันสิ้นสุด (ข้ามวันหยุดตามตั้งค่า) + สร้างตารางจากแม่แบบ
- คัดลอกตาราง/งบจากรุ่นก่อนได้
- ก่อนปิดรุ่น: เช็คลิสต์ความครบถ้วน (ประเมินหลังเรียน สถานะทุกคน ค่าตอบแทน รายงาน) ไม่ครบปิดไม่ได้

## 7. ทะเบียน ประวัติ และการป้องกันลงซ้ำ

### 7.1 การลงทะเบียน (Wizard)
1 เลขประจำตัวผู้ต้องขัง → 2 ข้อมูลส่วนตัว → 3 คดี → 4 ยาเสพติด/ประวัติบำบัด →
5 เกณฑ์รับเข้าของหลักสูตร → 6 ยืนยัน
- ใส่เลขประจำตัวที่มีอยู่แล้ว → ดึงข้อมูลมา + กล่องประวัติทุกหลักสูตร
- เลขใหม่ → ใส่เลขบัตรประชาชน → ค้นการต้องโทษครั้งก่อน ถ้าพบผูกเป็นบุคคลเดียวกัน
- ไม่มีเลขบัตร → เทียบชื่อ-สกุล + วันเกิด แสดง "อาจเป็นคนเดียวกัน" ให้ยืนยัน
- เลขประจำตัวแก้ไม่ได้หลังบันทึก (ยกเว้นผู้ดูแล พร้อมเหตุผล)

### 7.2 กฎลงซ้ำ
1. เลขประจำตัวเดียวกัน + หลักสูตรเดียวกัน → **บล็อก** (ไม่ว่ารุ่นก่อนจบหรือไม่)
   ปลดล็อกเฉพาะผู้ดูแล + เหตุผล + บันทึกผู้อนุมัติ
2. เลขประจำตัวใหม่ แต่บุคคลเดิมเคยผ่านหลักสูตรนี้ → ลงได้ เตือนสีเหลือง + ป้าย "กลับมาต้องโทษซ้ำ"
3. กำลังอยู่หลักสูตรอื่น → เตือนสีเหลือง ลงได้เมื่อยืนยัน

### 7.3 นำเข้าจาก Excel (รวมข้อมูลรุ่นเก่าย้อนหลัง)
- มีแม่แบบ Excel ให้ดาวน์โหลด
- ตรวจทุกแถวด้วยกฎข้างบน แสดงตาราง: ลงได้ / ซ้ำ (บล็อก) / กลับมาซ้ำ / อาจเป็นคนเดียวกัน / ข้อมูลผิดรูปแบบ
- นำเข้าเฉพาะแถวที่ผ่าน ดาวน์โหลดแถวที่ไม่ผ่านพร้อมเหตุผล
- รองรับนำเข้ารุ่นที่จบแล้วพร้อมสถานะ (เพื่อให้ประวัติและการกันซ้ำใช้ได้ตั้งแต่วันแรก)

### 7.4 การแสดงผล
- หน้าบุคคล: ไทม์ไลน์แยกตามการต้องโทษ และหลักสูตรในแต่ละครั้ง
- รายชื่อรุ่น: ป้ายหลักสูตรที่เคยผ่าน และ "กลับมาต้องโทษซ้ำ"

### 7.5 ข้อมูลติดต่อ
- ญาติ/ผู้ติดต่อ (ชื่อ ความสัมพันธ์ เบอร์), ที่อยู่หลังปล่อย, หน่วยบริการสาธารณสุขใกล้บ้าน

### 7.6 รูปถ่ายและข้อมูลเอกสาร
- แนบได้เฉพาะรูปถ่ายประจำตัว: ย่ออัตโนมัติ ด้านยาว 800 px + รูปเล็ก 200 px
  เก็บไฟล์ในโฟลเดอร์บนเซิร์ฟเวอร์ (ไม่เก็บในฐานข้อมูล) เปิดได้เฉพาะผู้ล็อกอิน
- เอกสาร (ใบตรวจแพทย์ ฯลฯ) **ไม่แนบไฟล์** บันทึกเป็นข้อมูล: ประเภท วันที่ ผล ผู้ออกเอกสาร
  หมายเหตุ ที่เก็บต้นฉบับ (เช่น แฟ้มรุ่น 1/2569)
- ออกแบบให้เพิ่มการแนบไฟล์ได้ภายหลังโดยไม่รื้อระบบ

## 8. บันทึกการออกจากเรือนจำ

ไม่กรอกวันพ้นโทษล่วงหน้า บันทึกเมื่อทราบว่าออกไปแล้วเท่านั้น
- บันทึกทีละหลายคน: วางเลขประจำตัวหลายเลข → แสดงชื่อ+รูปให้ตรวจ → วันที่ + เหตุผล → ยืนยัน
- เหตุผล (ตั้งค่าได้): พ้นโทษ / พักการลงโทษ / ลดวันต้องโทษ / ประกันตัว / ย้ายเรือนจำ / เสียชีวิต / อื่นๆ
- แก้ไข/ยกเลิกได้ ระบบย้อนการประมวลผลให้

ระบบทำอัตโนมัติ:
1. กำลังอบรม → สถานะ "ออกก่อนกำหนด" + ตัดออกจากเช็คชื่อ ผังบ้าน ทีมงาน ตั้งแต่วันนั้น
   ไม่นับ "ขาด" หลังจากนั้น ยกเลิก Shot down/LE/ประเมินค้าง
2. บสต.: สร้างงาน "บันทึกจำหน่าย"; ยังไม่จบ → งานติดตามที่เหลือเป็น "ติดตามไม่ได้ – (เหตุผล)"
   จบแล้ว → ตั้งค่าได้รายเหตุผลว่า "ติดตามต่อ" หรือ "ปิดการติดตาม"
3. ปรับตัวเลขทุกรายงาน
- แสดงสรุปสิ่งที่ระบบทำหลังบันทึก

## 9. การเช็คชื่อและการกรอกข้อมูลเร็ว

- เช็คชื่อรายกิจกรรม: มา / ขาด / ลา / ป่วย / **เหตุราชทัณฑ์** (ไปศาล / พบทนาย / ออก รพ.ภายนอก /
  เบิกตัวอื่นๆ — ระบุ) — ค่าเริ่มต้น "มา" ทั้งรุ่น แก้เฉพาะคนที่ไม่มา
  - "เหตุราชทัณฑ์" **ไม่นับเป็นขาด** ไม่หัก % การเข้าร่วม (ตัดออกจากตัวหาร)
  - แสดงป้าย "ควรจัดสอนชดเชย" ให้ผู้รับผิดชอบคาบ บันทึกคาบชดเชยได้ (ผูกกับคาบเดิม)
  - คาบชดเชยเบิกค่าตอบแทนได้หรือไม่ ตั้งค่าได้ (ค่าเริ่มต้น: ไม่ได้)
- ทุกแถวในหน้าเช็คชื่อ/กรอกเร็ว/ลงความเห็น มี **รูปย่อ 32×32 px** ติดชื่อเสมอ (กันผิดคนจากชื่อซ้ำ)
  กดค้างที่รูปเพื่อดูรูปใหญ่ + เลขประจำตัว + แดน; ชื่อซ้ำในรุ่นเดียวกันแสดงป้าย "ชื่อซ้ำ" สีส้ม
- กันเช็คซ้ำ: กิจกรรมเดียวกันมีบันทึกเดียว ถ้ามีคนเช็คแล้วแสดงผลเดิม
- สรุป % การเข้าร่วม เตือนเมื่อต่ำกว่าเกณฑ์, ชั่วโมงสะสมเทียบเป้า, "ครั้งที่ x/y"
- พิมพ์ใบเซ็นชื่อ/ใบเช็คชื่อพร้อมรายชื่อ
- **โหมดกรอกเร็ว**: ตาราง แถว=คน คอลัมน์=ข้อ ใช้แป้นพิมพ์อย่างเดียว Enter ไปช่องถัดไป
  รวมคะแนน/แปลผลทันที ค่านอกช่วงเป็นสีแดง (ใช้กับแบบประเมินและเช็คชื่อย้อนหลัง)
- พิมพ์แบบประเมินเปล่าที่มีชื่อ+เลขประจำตัวพิมพ์ไว้แล้ว ทั้งรุ่น
- [ภายหลัง] บัตรสมาชิกมี QR สแกนเช็คชื่อด้วยแท็บเล็ต

## 10. คลังแบบประเมิน ความเห็นสถานพยาบาล

### 10.1 คลังแบบประเมิน (สร้าง/แก้ได้)
- **วิธีทำแบบประเมิน (ผสม 2 แบบ)** — แบบประเมินทุกชนิดอยู่ในโปรแกรม (ข้อคำถาม คะแนน แปลผล) แต่ช่องทางกรอกต่างกัน:
  1) **เจ้าหน้าที่สัมภาษณ์/ประเมินเอง** (2Q 9Q 8Q คัดกรองโรคจิต สภาวะกาย/จิต สมรรถภาพร่างกาย
     ความก้าวหน้า 27 ข้อ ทบทวนสถานภาพ): ทำในโปรแกรมโดยตรงบนคอมพิวเตอร์/แท็บเล็ต ทีละข้อ
     ระบบคิดคะแนนและแจ้งเตือนทันที (เช่น 8Q เสี่ยง)
  2) **ผู้ต้องขังตอบเอง** (ความรู้ ทัศนคติ แรงจูงใจ PMHQ Rosenberg ความพึงพอใจ อุณหภูมิใจ):
     พิมพ์แบบประเมินเปล่าที่มีชื่อ+เลขประจำตัว+รหัสแบบพิมพ์ไว้ทั้งรุ่น → ทำบนกระดาษ →
     เจ้าหน้าที่กรอกด้วย "โหมดกรอกเร็ว" (ตาราง คน×ข้อ) → ระบบคิดคะแนน/แปลผล
  - **ผู้ต้องขังไม่ใช้งานโปรแกรมเองเด็ดขาด** (ไม่มีหน้าจอให้ผู้ต้องขังกรอก) เพื่อความปลอดภัยของข้อมูล
  - แบบใดก็กรอกได้ทั้ง 2 ช่องทาง (เผื่อเครื่องเสียหรือเปลี่ยนวิธี) บันทึกว่ากรอกจากกระดาษหรือทำในระบบ
  - เก็บแผ่นกระดาษต้นฉบับในแฟ้มรุ่น (ระบุที่เก็บได้)
- ชื่อแบบ, ข้อคำถาม, ตัวเลือกคะแนน, ข้อกลับคะแนน, สูตรรวม, เกณฑ์แปลผล, รอบ (ก่อน/ระหว่าง/หลัง/รายเดือน)
- ข้อมูลอ่อนไหวหรือไม่ (ถ้าใช่ → สิทธิ์สถานพยาบาล)
- เกณฑ์แจ้งเตือน (เช่น 8Q ระดับเสี่ยง → แจ้งสถานพยาบาลทันที)
- เก็บคะแนนเป็นตัวเลขรายข้อ ไม่แนบไฟล์
- กราฟเปรียบเทียบก่อน-หลังรายบุคคลและรายรุ่น
- แบบประเมินที่ต้องใส่ไว้ให้พร้อม: ดูหัวข้อ 15–17

### 10.2 ความเห็นเจ้าหน้าที่สถานพยาบาล
- วันที่, ผู้บันทึก, ผลคัดกรอง/ประเมินสุขภาพ, ความเห็น, ข้อแนะนำ, ส่งต่อ (ใช่/ไม่ใช่)
- หัวข้อในฟอร์มตั้งค่าได้, เป็นข้อมูลอ่อนไหว

## 11. ตารางกิจกรรม วิทยากร ค่าตอบแทน

### 11.1 อัตราค่าตอบแทน (ตั้งปีละครั้ง)
- ตาราง "อัตรา" ตั้งชื่อเอง: บาท/ชม., เพดานต่อวัน, ใช้ตั้งแต่ปีงบ
- จำนวนวิทยากรสูงสุดที่เบิกได้ตามลักษณะกิจกรรม (บรรยาย/อภิปราย/แบ่งกลุ่ม) ตั้งค่าได้ เตือนเมื่อเกิน

### 11.2 ทะเบียนวิทยากร
- ชื่อ, ภายใน/ภายนอก, หน่วยงาน, เบอร์, (เลขบัญชี ไม่บังคับ)
- วิทยากรภายในผูกกับบัญชีผู้ใช้

### 11.3 คลังหัวข้อ (ตั้งครั้งเดียวต่อหลักสูตร)
- ชื่อ, หลักสูตร, ชั่วโมงมาตรฐาน, ลักษณะกิจกรรม, สี
- ประเภทผู้รับผิดชอบ: ① รายบุคคล (กำหนดจำนวนสูงสุด เช่น 2 คน) ② ทั้งทีม (ใส่ทุกคนอัตโนมัติ เอาออกได้)
- เบิกได้/ไม่ได้ (ทั้งทีมค่าเริ่มต้น = ไม่ได้), อัตราที่ใช้แยกภายใน/ภายนอก
- หลายคน: ได้คนละเต็ม / หารเท่ากัน / กำหนดสัดส่วน
- ผู้รับผิดชอบประจำ (เติมให้ทุกรุ่นอัตโนมัติ)
- นำเข้าหัวข้อจากคู่มือทั้ง 3 หลักสูตรไว้ให้ก่อน ผู้ดูแลแค่ตรวจแก้
- แก้หลายหัวข้อพร้อมกันได้

### 11.4 ตารางของรุ่น
- สร้างจากแม่แบบหรือคัดลอกจากรุ่นก่อน (เลื่อนวันที่อัตโนมัติ)
- ปฏิทินรายสัปดาห์ ลากย้ายได้ กดช่องเปลี่ยนคน
- เปลี่ยนคนเป็นช่วง: "เปลี่ยน ก. เป็น ข. ทุกคาบตั้งแต่ ... ถึง ..."
- ตรวจ: ช่องไม่มีผู้รับผิดชอบ, สอนซ้อนเวลา, วิทยากรเกินที่เบิกได้, ชั่วโมงไม่ครบ
- ไอคอน 💰 คาบที่เบิกได้
- **วิทยากรหลายคนต่อคาบ** (ตัวอย่างหน้าจอ: การ์ดคาบในตารางรายวัน)
  - กดคาบ → หน้าแก้ไขมีรายชื่อวิทยากร + ปุ่ม "+ เพิ่มวิทยากร" / ปุ่ม × เอาออก
    (จำนวนสูงสุดตามคลังหัวข้อ เช่น 2 คน; ประเภท "ทั้งทีม" ไม่จำกัด)
  - เลือกได้ทั้งภายในและภายนอกในคาบเดียวกัน, ระบุบทบาท: วิทยากรหลัก / วิทยากรร่วม (ไม่บังคับ)
  - การ์ดคาบแสดงทุกชื่อ เช่น "วิภาวรรณ ฟื้นฟูใจ, ปวีณา รับฟัง" พร้อมป้ายใน/นอก
  - เปลี่ยนจาก 1 เป็น 2 คน (หรือกลับกัน) → **คำนวณค่าตอบแทนใหม่ทันที** ตามวิธีแบ่งของหัวข้อนั้น
    (คนละเต็มอัตรา / หารเท่ากัน / กำหนดสัดส่วน) และแสดงยอดของแต่ละคนในหน้าแก้ไขก่อนบันทึก
  - แก้วิธีแบ่งเฉพาะคาบนี้ได้ (ผู้ดูแล) พร้อมหมายเหตุ
  - ตรวจชนเวลา ตรวจเกินจำนวนที่เบิกได้ ทำกับทุกคนในคาบ
  - ปรากฏในตารางสอนของทุกคน, LINE แจ้งเตือน, หน้า "คาบของฉัน" (ใครก็บันทึกผลได้ บันทึกครั้งเดียวพอ),
    ใบสำคัญรับเงินของแต่ละคน (แถวของคาบนั้นแสดงยอดตามส่วนแบ่งของคนนั้น)

### 11.5 บันทึกการสอนจริงและผลกิจกรรม
- กด "สอนแล้ว" (ไม่แก้ = ถือว่าสอนตามตาราง) แก้ได้ถ้าเปลี่ยนคน/ยกเลิก/ชั่วโมงไม่เต็ม
- ผลกิจกรรม (≤ 30 วินาที): ตามแผน/บางส่วน/ไม่ได้ทำ (เหตุผล), การมีส่วนร่วม (ดีมาก–ควรปรับปรุง),
  สรุป 1–2 บรรทัด, ปัญหา/ข้อเสนอแนะ, จำนวนผู้เข้าร่วมดึงจากเช็คชื่อ
- เลยวันยังไม่กรอก → เตือนในหน้าแรกผู้รับผิดชอบ
- ค่าตอบแทนคิดจาก "สอนจริง"

### 11.5A วิทยากรภายใน vs ภายนอก (แยกชัดเจนทุกจุด)
**วิทยากรภายใน** = เจ้าหน้าที่ของเรือนจำเอง
- ผูกกับบัญชีผู้ใช้ (คนเดียวกัน) ข้อมูลดึงจากทะเบียนเจ้าหน้าที่ ไม่ต้องกรอกซ้ำ
- ข้อมูล: ตำแหน่ง ฝ่าย/งาน
- ใช้อัตรา "ภายใน" (ตั้งค่าได้ รวมถึงอัตรา 0 = ไม่เบิก)
- เห็นตารางสอนในหน้าแรกตัวเอง + ได้รับ LINE อัตโนมัติ
- ตรวจชนกับงานอื่นของตัวเอง (สอนซ้อน/เวร)
- สรุปภาระงานชั่วโมงสอนรายเดือน (รวมคาบที่เบิกไม่ได้) ใช้ประกอบการประเมินผลงาน

**วิทยากรภายนอก** = บุคลากรจากหน่วยงานอื่น
- ทะเบียนแยก: ชื่อ ตำแหน่ง หน่วยงานต้นสังกัด ประเภท (ราชการ/เอกชน/อาสาสมัคร/ภาคประชาสังคม)
  เบอร์โทร ที่อยู่ (สำหรับใบสำคัญรับเงิน) ความเชี่ยวชาญ หัวข้อที่เคยสอน
- เลขบัตรประชาชนและเลขบัญชีเป็นข้อมูลอ่อนไหว ปิดบัง เห็นเฉพาะการเงิน/ผู้ดูแล
- ใช้อัตรา "ภายนอก" แยกตามประเภทได้ (เช่น ราชการ vs เอกชน)
- หักภาษี ณ ที่จ่าย: เปิด/ปิดและ % ตั้งค่าได้ แสดงยอดก่อนหัก/หลังหัก
- ค่าใช้จ่ายอื่นของวิทยากรภายนอก (ถ้ามี): ค่าพาหนะ ค่าที่พัก — บันทึกแยกรายการ
- เอกสารอัตโนมัติ: หนังสือเชิญ, บันทึกขออนุมัติเชิญ, ใบสำคัญรับเงิน, หนังสือขอบคุณหลังสอน
- สถานะการเชิญต่อคาบ: ยังไม่เชิญ / ส่งหนังสือแล้ว / ตอบรับ / ปฏิเสธ / ยืนยันวันสอน
  เตือนถ้าอีก 14 วันจะถึงคาบแต่ยังไม่ตอบรับ
- ไม่ได้รับ LINE อัตโนมัติ ใช้ปุ่มคัดลอกข้อความแจ้งรายคนแทน
- ประวัติการสอน + ความพึงพอใจของผู้เข้าอบรม (ถ้ามี) ช่วยเลือกวิทยากรครั้งต่อไป

**การแสดงผลให้แยกชัด**
- ปฏิทินและตาราง: ป้าย "ใน" (สีน้ำเงิน) / "นอก" (สีส้ม) ทุกคาบ
- ตัวกรองในทุกหน้าที่เกี่ยวข้อง: ทั้งหมด / ภายใน / ภายนอก
- คาบเดียวมีทั้งภายในและภายนอกร่วมกันได้ คิดเงินแยกตามอัตราของแต่ละคน
- เปลี่ยนตัวคนสอนจากภายในเป็นภายนอก (หรือกลับกัน) ระบบคำนวณเงินใหม่และแจ้งเอกสารที่ต้องทำเพิ่ม

**รายงานแยกภายใน/ภายนอก**
- จำนวนคาบ ชั่วโมง และค่าตอบแทน แยกภายใน/ภายนอก รายรุ่น/หลักสูตร/เดือน/ปีงบ
- สัดส่วนชั่วโมงภายใน:ภายนอกของแต่ละหลักสูตร
- รายชื่อวิทยากรภายนอกพร้อมหน่วยงาน (ใช้ในแบบรายงานกรมฯ หัวข้อ "วิทยากรภายนอกที่ให้การสนับสนุน")
- งบประมาณ: ค่าตอบแทนวิทยากรแยกบรรทัด ภายใน / ภายนอก

### 11.5B ฐานข้อมูลวิทยากร (กรอกครั้งเดียว ใช้เติมเอกสารทุกฉบับ)
- หน้า "ทะเบียนวิทยากร" เพิ่ม/แก้/ค้นหา ทั้งภายในและภายนอก
- ข้อมูลที่ต้องมีเพื่อเติมเอกสารเบิกจ่าย (แยกช่องตามแบบฟอร์ม ไม่ใช่ช่องที่อยู่ช่องเดียว):
  - ตัวตน: คำนำหน้า ชื่อ นามสกุล, ตำแหน่ง, หน่วยงาน, ภายใน/ภายนอก
  - เลขประจำตัวประชาชน/เลขผู้เสียภาษีอากร 13 หลัก (ตรวจ check digit)
  - ที่อยู่: บ้านเลขที่ หมู่ที่ ซอย ถนน ตำบล/แขวง อำเภอ/เขต จังหวัด รหัสไปรษณีย์
    (ตำบล-อำเภอ-จังหวัด-รหัสไปรษณีย์ เลือกจากรายการ เลือกตำบลแล้วเติมที่เหลือให้อัตโนมัติ)
  - ติดต่อ: เบอร์โทรมือถือ, อีเมล
  - การรับเงินโอน: ประเภทผู้รับ (บุคคลธรรมดา / บริษัท-ห้างหุ้นส่วน-ร้านค้า + ชื่อนิติบุคคล),
    ธนาคาร (เลือกจากรายการ), สาขา, ประเภทบัญชี (ออมทรัพย์/กระแสรายวัน/ฝากประจำ),
    ชื่อบัญชี, เลขที่บัญชี (จัดรูปแบบอัตโนมัติ), ช่องทางแจ้งผลการโอน (SMS / อีเมล / ทั้งสอง)
  - ติ๊ก "ได้รับสำเนาหน้าสมุดบัญชีแล้ว" + วันที่ได้รับ (ไม่แนบไฟล์ เก็บสำเนากระดาษที่แฟ้ม)
  - ใช้ได้กับวิทยากรทุกคน ทั้งภายในและภายนอก
- เลขบัญชีเป็นข้อมูลอ่อนไหว: ปิดบังในหน้าจอ (xxx-x-x1234-x) เห็นเต็มเฉพาะการเงิน/ผู้ดูแล
- หน้าทะเบียนวิทยากรแสดงสถานะความครบ: "พร้อมเบิก" (เขียว) / "ข้อมูลไม่ครบ: ขาดเลขบัญชี ..." (แดง)
- พิมพ์ "แบบฟอร์มขอข้อมูลวิทยากร" เปล่า (หรือเติมเท่าที่มี) ให้วิทยากรกรอกมือ แล้วนำมาบันทึกเข้าระบบ
- วิทยากรภายใน: ข้อมูลส่วนตัวดึงจากบัญชีเจ้าหน้าที่ เติมเฉพาะที่อยู่/เลขบัตร
- ตอนพิมพ์ ถ้าข้อมูลวิทยากรไม่ครบ ให้เตือนพร้อมลิงก์ไปกรอก (หรือพิมพ์เว้นช่องว่างไว้ให้เขียนมือได้)
- เลขบัตรและที่อยู่เป็นข้อมูลอ่อนไหว เห็นเฉพาะการเงิน/ผู้ดูแล แต่แสดงเต็มในเอกสารที่พิมพ์

### 11.5C ใบสำคัญรับเงิน (สำหรับวิทยากร) — ตามแบบฟอร์มที่เจ้าของให้มา
ใช้เฉพาะค่าตอบแทนวิทยากรในการบรรยาย / 1 แผ่น A4 ต่อวิทยากร 1 คน ต่อ 1 รุ่น
รูปแบบ (เรียงตามแบบฟอร์มต้นฉบับ มีกรอบรอบหน้า):
- หัว: "ใบสำคัญรับเงิน (สำหรับวิทยากร)" ตัวหนา กึ่งกลาง
- ชื่อส่วนราชการผู้จัดฝึกอบรม …… (จากตั้งค่าหน่วยงาน)
- โครงการ/หลักสูตร …… (ชื่อหลักสูตร + รุ่นที่ + ปีงบ)
- วันที่ … เดือน … พ.ศ. … (ชิดขวา, ค่าเริ่มต้น = วันสุดท้ายของรุ่น แก้ได้ตอนพิมพ์)
- ข้าพเจ้า …… เลขที่บัตรประจำตัวประชาชน ……
- อยู่บ้านเลขที่ … หมู่ที่ … ซอย … ถนน … ตำบล … อำเภอ … จังหวัด … เบอร์โทรศัพท์ …
  (ช่องที่ไม่มีข้อมูลใส่ "-")
- ได้รับเงินจาก …… (ชื่อส่วนราชการ) ดังรายละเอียดต่อไปนี้
- ตาราง: รายการ | จำนวนเงิน (บาท | สต.)
  **1 แถว = 1 คาบที่สอนจริง** มีเลขลำดับ เรียงตามวันที่ รูปแบบ:
  "1. วันที่ 5 ต.ค. 2569 หัวข้อ ทักษะการปฏิเสธ 1.5 ชม. × 600 บาท = 900 บาท"
  (วันเดียวสอนหลายหัวข้อ = หลายแถว) สอน 10 วันก็มีครบทุกวันทุกหัวข้อ
- ตารางยาวเกินหน้า: ขึ้นหน้าใหม่ หัวตารางซ้ำ มี "ยอดยกไป/ยอดยกมา" ท้าย/ต้นหน้า
  ส่วนรวมเงิน ตัวอักษร และลายเซ็น อยู่หน้าสุดท้ายเสมอ (หัวกระดาษหน้าถัดไปมีชื่อวิทยากร + "หน้า x/y")
- แถวว่างที่เหลือในหน้าสุดท้ายคงเส้นตารางไว้ตามต้นฉบับ
- ช่วงเวลาที่เบิก: ทั้งรุ่น (ค่าเริ่มต้น) หรือเลือกช่วงวันที่ (เช่น เบิกรายเดือนสำหรับชุมชนบำบัด 6 เดือน)
  คาบที่เบิกไปแล้วถูกล็อก ไม่ถูกนำมาเบิกซ้ำในใบถัดไป
- รวมเป็นเงิน (บาท | สต.)
- จำนวนเงิน … (ตัวอักษร) … — แปลงเป็นข้อความภาษาไทยอัตโนมัติ เช่น "เก้าพันบาทถ้วน",
  "หนึ่งพันห้าร้อยบาทห้าสิบสตางค์" (มี unit test ครอบคลุม)
- ลงชื่อ …… ผู้รับเงิน (ชื่อวิทยากรพิมพ์ในวงเล็บให้แล้ว)
- ลงชื่อ …… ผู้จ่ายเงิน (ชื่อผู้จ่ายเงินจากตั้งค่า เปลี่ยนได้ตอนพิมพ์)
- ถ้าเปิดหักภาษี ณ ที่จ่าย: เพิ่มแถว "หัก ภาษี ณ ที่จ่าย …%" และยอดสุทธิ (เปิด/ปิดในตั้งค่า)
- ไม่ใส่ท้ายกระดาษ "พิมพ์โดย" ในเอกสารนี้ (เพื่อให้ตรงแบบฟอร์มราชการ) แต่บันทึกการพิมพ์ใน audit log

การพิมพ์:
- ปุ่ม "พิมพ์ใบสำคัญรับเงินทั้งรุ่น" → PDF เดียว ทุกวิทยากรที่เบิกได้ในรุ่น คนละหน้า
  เรียงตามชื่อ หรือตามวันที่สอนครั้งแรก
- เลือกพิมพ์เฉพาะบางคน / เฉพาะภายนอก / เฉพาะภายใน ได้
- ใช้ข้อมูลจาก "สอนจริง" (หัวข้อ 11.5) เท่านั้น
### 11.5D แบบแจ้งข้อมูลการรับเงินโอนผ่านระบบ KTB Corporate Online
พิมพ์คู่กับใบสำคัญรับเงินเสมอ (วิทยากร 1 คน = ใบสำคัญรับเงิน + แบบแจ้งข้อมูลการรับเงินโอน)
ใช้กับทุกคน เติมจากฐานข้อมูลวิทยากรทั้งหมด จัดให้พอดี A4 1 หน้า (ลายเซ็นอยู่หน้าเดียวกัน)
รูปแบบตามต้นฉบับ:
- หัว: "แบบแจ้งข้อมูลการรับเงินโอนผ่านระบบ KTB Corporate Online" ตัวหนา กึ่งกลาง
- วันที่ … เดือน … พ.ศ. … (ชิดขวา, ใช้วันเดียวกับใบสำคัญรับเงิน)
- เรียน …… (ตำแหน่งผู้บริหารสูงสุดจากตั้งค่าหน่วยงาน เช่น "ผู้บัญชาการเรือนจำกลาง…" ห้ามเขียนตายตัว)
- ข้าพเจ้า …… (คำนำหน้า ชื่อ นามสกุล)
- เลขประจำตัวประชาชน/เลขประจำตัวผู้เสียภาษีอากร: กล่อง 13 ช่อง ใส่ตัวเลขช่องละ 1 หลัก
- อยู่บ้านเลขที่ … (รวม "หมู่ x" ถ้ามี) ซอย … ถนน … ตำบล/แขวง … อำเภอ/เขต … จังหวัด … รหัสไปรษณีย์ …
- ข้อความ: ขอรับเงินผ่านระบบ KTB Corporate Online โดยได้แนบสำเนาหน้าสมุดบัญชีเงินฝากธนาคารมาเพื่อเป็นหลักฐานด้วยแล้ว
- ☐ กรณีเป็นบุคคลธรรมดา เพื่อเข้าบัญชีเงินฝากธนาคาร … สาขา … ประเภท … ชื่อบัญชี … เลขที่ …
- ☐ กรณีเป็นบริษัทฯ ห้างหุ้นส่วนจำกัด ฯลฯ เพื่อเข้าบัญชีเงินฝากธนาคาร … สาขา … ประเภท … ชื่อบัญชี … เลขที่ …
  + หมายเหตุตัวหนาเรื่องชื่อบัญชีไม่ตรงกับชื่อนิติบุคคล (ตามต้นฉบับ)
  → ติ๊ก ☑ และเติมข้อมูลเฉพาะช่องที่ตรงกับประเภทผู้รับ อีกช่องเว้นว่าง
- และเมื่อ (ชื่อหน่วยงานจากตั้งค่า) โอนเงินผ่านระบบ KTB Corporate Online แล้ว ให้ส่งข้อมูลการโอนเงินผ่านช่องทาง
  ☐ SMS ที่เบอร์โทรศัพท์ … / ☐ e-mail address … → ติ๊กและเติมตามที่วิทยากรเลือก
- ลงชื่อ …… ผู้มีสิทธิรับเงิน (ชื่อพิมพ์ในวงเล็บให้แล้ว)
- ถ้าข้อมูลส่วนใดไม่ครบ พิมพ์เส้นจุดว่างไว้ให้เขียนมือ และเตือนก่อนพิมพ์
- ตั้งค่าได้: แสดง/ไม่แสดงแบบฟอร์มนี้ในชุดเอกสาร (เผื่อบางคนรับเงินสด) — ค่าเริ่มต้น = แสดง
- เก็บแม่แบบเป็นไฟล์แก้ไขได้ (ผู้ดูแลปรับข้อความได้ถ้าธนาคาร/การเงินเปลี่ยนแบบฟอร์ม)

- **ชุดเอกสารส่งการเงิน** (ปุ่มเดียว ได้ PDF เรียงตามนี้):
  1) **สรุปใหญ่ค่าตอบแทนวิทยากร** ของรุ่น/ช่วงที่เลือก:
     ลำดับ | ชื่อ-สกุล | ภายใน/ภายนอก | จำนวนคาบ | จำนวนชั่วโมง | จำนวนเงิน | ลายมือชื่อผู้รับเงิน
     แยกกลุ่มภายใน / ภายนอก พร้อมยอดรวมย่อยแต่ละกลุ่ม → **ยอดรวมทั้งสิ้น** (ตัวเลข + ตัวอักษร)
     ท้ายกระดาษ: ช่องลงนาม ผู้จัดทำ / ผู้ตรวจสอบ / ผู้อนุมัติ, งบที่ได้รับ / เบิกครั้งนี้ / คงเหลือ
  2) **ใบสำคัญรับเงินรายบุคคล + แบบแจ้งข้อมูลการรับเงินโอน KTB** ทุกคน
     เรียงเป็นคู่: ใบสำคัญรับเงิน (คนที่ 1) → แบบ KTB (คนที่ 1) → ใบสำคัญรับเงิน (คนที่ 2) → ...
     ตัวเลือกพิมพ์สองหน้า: ให้แต่ละเอกสารเริ่มหน้าใหม่เสมอ
  3) [ตัวเลือก] ตารางรายละเอียดทั้งหมด เรียงตามวันที่: วันที่ | หัวข้อ | วิทยากร | ชม. | อัตรา | เงิน
- ตรวจก่อนพิมพ์: ยอดรวมในสรุปใหญ่ = ผลรวมใบสำคัญรับเงินทุกใบ = ผลรวมรายคาบ ถ้าไม่ตรงห้ามพิมพ์และบอกจุดผิด
- ส่งออก Excel ของสรุปใหญ่และรายละเอียดได้
- บันทึกสถานะต่อใบ: ยังไม่พิมพ์ / พิมพ์แล้ว / เซ็นรับแล้ว (ติ๊กเมื่อได้ใบที่เซ็นกลับมา)
  และเตือนในหน้าการเงินว่าใบไหนยังไม่ได้ลายเซ็น
- แก้ข้อมูลหลังพิมพ์แล้ว → เตือนว่าต้องพิมพ์ใหม่

### 11.6 สรุปค่าตอบแทน
- รายวิทยากร/รุ่น/เดือน/ปีงบ แยกภายใน-ภายนอก
- แสดงที่มาทุกบรรทัด: วันที่ หัวข้อ ชม. อัตรา วิธีแบ่ง = ยอด

- สรุปชั่วโมงสอนทุกคน รวมที่เบิกไม่ได้ (ภาระงาน)

## 14. บสต. และ รท.101 (แยกเป็น 2 งาน — เป็นตัวชี้วัดทั้งคู่)

โปรแกรมไม่เชื่อมต่อระบบภายนอกโดยตรง ทำหน้าที่ "เตือนและเช็คว่าลงแล้วหรือยัง"
ทั้งสองงานแยกเมนู แยกรายการค้าง แยกรายงาน แยกตัวชี้วัด (ไม่ปนกัน)
ตั้งค่ารายหลักสูตรแยกกัน: "ต้องลง บสต." / "ต้องลง รท.101" (เปิด/ปิด)

### 14.1 บสต. (รายละเอียดมาก — ลงทะเบียนและติดตามตามเกณฑ์)
- ค่าเริ่มต้น: 12 วัน และ ชุมชนบำบัด 6 เดือน = ต้องลง / 3 วัน = ไม่ต้องลง
- เลขประจำตัวใน บสต. ต่อคน
- ขั้นตอนต่อคนต่อหลักสูตร (ตั้งค่าได้): ลงทะเบียน → คัดกรอง → บำบัด → จำหน่าย (จบกระบวนการ)
  → ติดตามเดือนที่ 1, 3, 6, 12 (รวม 4 ครั้ง)
- กำหนดวันครบกำหนดของแต่ละขั้นอัตโนมัติ (ลงทะเบียน/คัดกรอง นับจากวันเข้า, จำหน่าย นับจากวันจบ,
  ติดตาม นับจากวันจำหน่าย) — จำนวนวันที่ต้องลงภายในกำหนดตั้งค่าได้
- แต่ละขั้น: ปุ่ม "ลง บสต. แล้ว" บันทึกวันที่ + ผู้ลงอัตโนมัติ, สถานะสี เขียว/เหลือง/แดง
- ผลการติดตามแต่ละครั้ง: วันที่, วิธี (โทร/เยี่ยม/ส่งต่อ), ผลตรวจปัสสาวะ (ถ้ามี),
  กลับไปเสพซ้ำ ใช่/ไม่ใช่/ไม่ทราบ, อาชีพ, หมายเหตุ
- ติดตามไม่ได้ (พ้นโทษ/ย้าย/เสียชีวิต/อื่นๆ) ไม่นับค้าง แต่แสดงแยกพร้อมเหตุผล
- หน้าแรก: กล่อง "งาน บสต." วันนี้ / ภายใน 7 วัน / เลยกำหนด เตือนซ้ำจนกด "ลงแล้ว"
- รายงาน บสต.: รายบุคคล (ครบ/ไม่ครบ ขาดขั้นไหน กี่ครั้ง) / รายรุ่น / รายหลักสูตร / ปีงบ
  (% ลงครบตามเกณฑ์, ค้าง, ติดตามไม่ได้แยกเหตุผล), รายชื่อค้างลงพิมพ์เป็นเช็คลิสต์
- ตัวชี้วัด: % ลงทะเบียน บสต. ครบ, % ติดตามครบ 4 ครั้ง, % ไม่กลับไปเสพซ้ำใน 1 ปี (จากผลติดตาม)

### 14.2 รท.101 (ง่าย — บันทึกว่าผ่านการฟื้นฟูแล้ว ครั้งเดียว)
- ลงในระบบข้อมูลผู้ต้องขังของเรือนจำ (รท.101) ว่า "คนนี้ผ่านการฟื้นฟูแล้ว" เท่านั้น
- เกิดงาน 1 รายการต่อคนต่อหลักสูตร เมื่อสถานะเป็น "ครบหลักสูตร" (คนไม่จบไม่ต้องลง)
- ปุ่ม "ลง รท.101 แล้ว" (ติ๊กทีละหลายคนได้) บันทึกวันที่ + ผู้ลง
- ไม่มีการติดตาม ไม่มีหลายขั้น
- ค่าเริ่มต้นหลักสูตรที่ต้องลง: **ทั้ง 3 หลักสูตร** (12 วัน, ชุมชนบำบัด 6 เดือน, 3 วันก่อนปล่อย)
- หน้าแรก: ตัวเลข "รท.101 ค้างลง x คน" กดแล้วเห็นรายชื่อ
- รายงาน/ตัวชี้วัด: จำนวนผู้จบหลักสูตร vs ลง รท.101 แล้ว → % ลงครบ รายรุ่น/หลักสูตร/ปีงบ

### 14.3 ส่วนที่ใช้ร่วมกัน
- บันทึกออกจากเรือนจำ (หัวข้อ 8) ปรับงาน บสต. ให้อัตโนมัติ; งาน รท.101 ยังคงอยู่ถ้าจบหลักสูตรแล้ว
- แบบรายงานกรมฯ หัวข้อ "การนำเข้าข้อมูล บสต. และ รท.101" แสดงเป้าหมาย/ดำเนินการจริง แยกสองบรรทัด
- เปิดหลักสูตรให้ต้องลงภายหลัง → เลือกได้ว่าสร้างงานย้อนหลังหรือไม่

2. คดี: ฐานความผิด, กำหนดโทษ (ปี/เดือน/วัน), โทษที่เหลือ (ปี/เดือน/วัน)
3. ข้อมูลเกี่ยวข้อง: สภาพที่อยู่อาศัยก่อนต้องโทษ (ข้อความยาว), ความผูกพันในครอบครัว (ข้อความยาว)

**ส่วนที่ 2 แบบประเมิน** (สถานพยาบาลเห็นส่วนสุขภาพ, ฟื้นฟูเห็นส่วนความรู้/ทัศนคติ/พฤติกรรม)
2.1 แบบประเมินสภาวะร่างกาย/จิตใจในการเข้ารับการบำบัด
- ตรวจร่างกาย: วันที่ น้ำหนัก ส่วนสูง (BMI คำนวณ) ความดัน ชีพจร ความพิการ (บันทึกได้หลายครั้ง)
- ประวัติโรคทางกาย: ไม่มี / มี (ระบุโรค) → ยังรักษาต่อเนื่อง / ยุติการรักษาแล้ว
- ผลคัดกรองสุขภาพจต: ดึงคะแนน PMHQ-Thai, 2Q, 9Q, 8Q, คัดกรองโรคจิต อัตโนมัติ
- ประวัติจิตเวช: ไม่มี / มี (ระบุ) → ยังรักษา / ยุติแล้ว
- ประวัติใช้สารเสพติด (หลายแถว): สารที่ใช้, อายุที่เริ่มใช้,
  ความถี่ (ทุกวัน / 5–6 วัน/สัปดาห์ / 3–4 วัน/สัปดาห์ / 1–2 วัน/สัปดาห์ / เดือนละ … ครั้ง)
- ความเห็นผู้ประเมิน: ☐ เข้าร่วมได้ (ไม่มีปัญหาจิตเวช / ไม่มีปัญหากาย ที่เป็นอุปสรรค)
  ☐ ยังเข้าร่วมไม่ได้ (มีปัญหาจิตเวช / มีปัญหากาย) + ผู้ประเมิน + วันที่
  → ถ้า "ยังเข้าร่วมไม่ได้" ระบบไม่ให้ยืนยันรับเข้า (ยกเว้นผู้ดูแล)
2.2 PMHQ-Thai 24 ข้อ (0–3) รวม 0–28 ปกติ / ≥ 29 มีปัญหาสุขภาพจิต
2.3 2Q → 9Q → 8Q (ทำเป็นลำดับขั้นอัตโนมัติ)
- 2Q: 2 ข้อ มี/ไม่มี — "ไม่มี" ทั้งคู่ = ปกติ จบ / "มี" ข้อใดข้อหนึ่ง → เปิด 9Q
- 9Q: 9 ข้อ (0–3) — 0–6 ไม่มีภาวะซึมเศร้า / 7–12 น้อย / 13–18 ปานกลาง / ≥ 19 รุนแรง
  ≥ 7 → เปิด 8Q / ≥ 13 → เตือน "พิจารณาส่งพบจิตแพทย์"
- 8Q: น้ำหนักคะแนนต่อข้อ (ไม่มี/มี) ข้อ1=1, ข้อ2=2, ข้อ3=6
  (ถ้าข้อ 3 = มี → ถามต่อ "ควบคุมได้ไหม" ได้=0 ไม่ได้=8), ข้อ4=8, ข้อ5=9, ข้อ6=4, ข้อ7=10, ข้อ8=4
  0 ไม่มีแนวโน้ม / 1–8 น้อย / 9–16 ปานกลาง / ≥ 17 รุนแรง
- 8Q ≥ 1: แจ้งเตือนสถานพยาบาลทันที แสดง "แนวทางการดูแล" ตามระดับ (ตามแนวทางกรมสุขภาพจิต
  ที่อยู่ในสมุด) เป็นคำแนะนำ ไม่ใช่การวินิจฉัย; ≥ 17 เป็นแจ้งเตือนเร่งด่วนสีแดง
2.4 คัดกรองโรคจิต 11 ข้อ (มี=1): สัมภาษณ์คนใกล้ชิด 8 ข้อ + สัมภาษณ์ผู้ป่วย 3 ข้อ
  รวม ≥ 1 = สงสัยโรคจิต → แจ้งสถานพยาบาล (มีคำอธิบายแต่ละข้อจากคู่มือให้กด (?) ดู)
2.5 แบบประเมินความรู้ความเข้าใจเกี่ยวกับยาเสพติด 15 ข้อ ถูก/ผิด (ก่อน-หลัง) ข้อละ 1 คะแนน เต็ม 15
  เฉลย: ข้อที่ถูกคือ 1,2,4,7,8,11,12,13,15 / ข้อที่ผิดคือ 3,5,6,9,10,14
  (เก็บเฉลยเป็นค่าตั้ง ผู้ดูแลแก้ได้) ระดับ: ผู้ดูแลกำหนดช่วงคะแนนได้
2.6 แบบสอบถามทัศนคติต่อการใช้สารเสพติด 21 ข้อ (5–1) ก่อน-หลัง
  ข้อเชิงบวก (+) คิดตรง: 3,4,5,6,10,11,14,18,19,20,21
  ข้อเชิงลบ (−) กลับคะแนน: 1,2,7,8,9,12,13,15,16,17
  รวม 77–105 สูง / 49–76 ปานกลาง / 21–48 ต่ำ
2.7 แบบสอบถามขั้นบันไดแรงจูงใจ (ก่อน-หลัง) เลือก 1 ขั้น:
  ก. ยังไม่คิดจะหยุด / ข. วันหนึ่งจะไตร่ตรอง / ค. ควรลดแต่ยังไม่พร้อม /
  ง. เริ่มคิดหาวิธีเปลี่ยน / จ. เริ่มลงมือเปลี่ยน → แสดงการขยับขั้นก่อน→หลัง
2.8 แบบประเมินความก้าวหน้าสมาชิก 27 ข้อ 10 ด้าน (1–5) โดยเจ้าหน้าที่
  ชุมชนบำบัด: ทุกสิ้นเดือน / 12 วัน: หลังจบหลักสูตร
  รวม 27–63 ต่ำ/ต้องปรับปรุง / 64–99 ปานกลาง / 100–135 ดี (สมุดเขียน 64–100 ซ้อนกับ 100 ให้ใช้ 64–99)
2.9 หน้าสรุปผลรายบุคคล (ตามสมุด): ตาราง ก่อน/หลัง ของความรู้ ทัศนคติ แรงจูงใจ
  และผลความก้าวหน้า (วันที่ คะแนน ระดับ) สร้างอัตโนมัติ + ช่องลงชื่อผู้บันทึก

**ส่วนที่ 3 ความก้าวหน้าของพฤติกรรมและการให้ความช่วยเหลือในแต่ละเดือน**
- 1 บันทึกต่อเดือน: ข้อความบรรยาย (ช่องยาว) + ผู้บันทึก + วันที่
- แสดงข้อมูลช่วยเขียนของเดือนนั้นข้างๆ: % เข้าร่วม, คะแนนพฤติกรรมเดือนนี้, เครื่องมือบ้านที่ใช้,
  การละเมิดกฎ, ตำแหน่ง/ทีมที่เปลี่ยน (ผู้บันทึกกด "แทรกสรุป" ใส่ในข้อความได้ แล้วแก้ต่อ)
- เตือนสิ้นเดือนถ้ายังไม่เขียน

**ส่วนที่ 4 ความเห็นของที่ปรึกษา**
- ข้อความบรรยาย + ชื่อที่ปรึกษา + วันที่ (เขียนได้หลายครั้ง แสดงล่าสุดก่อน)

**การพิมพ์สมุด**
- พิมพ์ทั้งเล่มหรือเลือกส่วน, รูปแบบตามต้นฉบับ (ฟอนต์ TH Sarabun New)
- แบบประเมินที่ยังไม่ได้ทำ พิมพ์เป็นฟอร์มเปล่ามีชื่อพิมพ์ไว้ ให้กรอกด้วยมือได้
- ข้อมูลสุขภาพพิมพ์ได้เฉพาะผู้มีสิทธิ์ ถ้าไม่มีสิทธิ์จะพิมพ์ส่วนนั้นเป็น "ข้อมูลจำกัดสิทธิ์"
- หมายเหตุ: PMHQ-Thai สงวนลิขสิทธิ์โดยกรมราชทัณฑ์ ใช้ภายในหน่วยงานตามที่ได้รับ ไม่เผยแพร่ภายนอก

**ใช้ร่วมกับหลักสูตร 12 วัน**: แบบประเมิน 2.1–2.9 เป็นชุดเดียวกับที่ 12 วันใช้
เก็บในคลังแบบประเมินกลาง (หัวข้อ 10) ทั้งสองหลักสูตรเรียกใช้ ไม่สร้างซ้ำ

### 16B. เกณฑ์คิดคะแนนจากแบบฟอร์มจริง (ภาพต้นฉบับใน docs/forms/ — ยึดตามภาพเสมอ)

**Rosenberg มี 2 ฉบับ — แยกเป็น 2 แบบในคลัง ห้ามรวมกัน (ข้อ 8 ต่างกัน)**
- ฉบับ 3 วัน (กรมราชทัณฑ์): บวก 1,3,4,7,10 / ลบ (กลับคะแนน) 2,5,6,8,9
  ข้อ 8 = "อยากจะภาคภูมิใจในตัวเองมากกว่านี้" → 10–20 ต่ำ / 21–30 ปานกลาง / 31–40 สูง
- ฉบับชุมชนบำบัด FAST "สำหรับผู้ป่วยยาเสพติดระยะฟื้นฟูสมรรถภาพ" (ช่วง 2 สัปดาห์ที่ผ่านมา):
  บวก 1,3,4,7,8,10 / ลบ 2,5,6,9 (ข้อ 8 = "เชื่อว่าสมควรได้รับความนับถือ")
  บวก: เห็นด้วยอย่างยิ่ง 4 → ไม่เห็นด้วยอย่างยิ่ง 1 / ลบ: กลับกัน
  6 ระดับ + แนวทางจัดการ (แสดงคู่กับผล):
  35–40 สูงมาก (เสริมแรง ป้องกันความอหังการ) / 30–34 สูง (ส่งเสริมทักษะเฉพาะด้าน) /
  25–29 ปานกลาง (พัฒนาจุดแข็ง แก้จุดอ่อน) / 20–24 ค่อนข้างต่ำ (ช่วยเหลือเฉพาะด้าน) /
  15–19 ต่ำ (ต้องการการบำบัดเร่งด่วน → แจ้งที่ปรึกษา) / 10–14 ต่ำมาก (ช่วยเหลือเข้มข้นและติดตาม → แจ้งที่ปรึกษา+นักจิตวิทยา)
  ข้อมูลหัวแบบ: วันที่ประเมิน, ระยะการบำบัด (entry/rehab/re-entry/after care — เติมอัตโนมัติจากระยะปัจจุบัน),
  ประเภทยาเสพติดหลัก, ระยะเวลาที่เลิกเสพ
- รายงานข้ามหลักสูตรเทียบด้วยคะแนนดิบ (10–40) เท่านั้น

**แบบสอบถามคุณภาพชีวิตผู้ใช้สารเสพติด (WHOQOL-26) — ช่วง 2 สัปดาห์ที่ผ่านมา**
- 26 ข้อ 5 ตัวเลือก: ไม่เลย / เล็กน้อย / ปานกลาง / มาก / มากที่สุด
- ข้อทางบวก 23 ข้อ: 1→5 / ข้อทางลบ (กลับคะแนน) **2, 9, 11**: ไม่เลย=5 ... มากที่สุด=1
- รวม 26–130: 26–60 ไม่ดี / 61–95 กลางๆ / 96–130 ดี
- รายด้าน:
  ร่างกาย (ข้อ 2,3,4,10,11,12,24) 7–16 ไม่ดี / 17–26 กลางๆ / 27–35 ดี
  จิตใจ (5,6,7,8,9,23) 6–14 / 15–22 / 23–30
  สัมพันธภาพทางสังคม (13,14,25) 3–7 / 8–11 / 12–15
  สิ่งแวดล้อม (15,16,17,18,19,20,21,22) 8–18 / 19–29 / 30–40
  ข้อ 1 และ 26 ไม่อยู่ในด้านใด แต่รวมในคะแนนรวม
- แสดงกราฟ 4 ด้าน ก่อน-หลัง; ข้อ 25 (ชีวิตทางเพศ) เป็นข้อมูลอ่อนไหว ไม่แสดงรายข้อในรายงาน

**SCL-90-R — ช่วง 7 วันที่ผ่านมา**
- 90 ข้อ 0–4 (ไม่เลย / เล็กน้อย / ค่อนข้างมาก / มาก / มากที่สุด) ตามภาพต้นฉบับ
- ระหว่างยังไม่ได้หน้าวิธีคิดคะแนนรายด้านจากคู่มือ: แสดงเฉพาะ คะแนนรวม, GSI (คะแนนรวม ÷ 90),
  จำนวนข้อที่ตอบมากกว่า 0 — **ไม่ติดป้ายระดับ ไม่แบ่งด้าน**
- ข้อมูลสุขภาพจิต เห็นเฉพาะพยาบาล/นักจิตวิทยา
- ข้อ 15 (คิดอยากจบชีวิต) และ 59 (คิดถึงความตาย) ตอบ ≥ 1 → แจ้งเตือนพยาบาล/นักจิตวิทยาทันที
  (เป็นสัญญาณให้ประเมินด้วย 8Q ต่อ ไม่ใช่การวินิจฉัย)
- ข้อ 63 (อยากทำร้ายผู้อื่น), 67 (อยากทำลายข้าวของ) ตอบ ≥ 3 → แจ้งเตือนเช่นกัน

**ลิขสิทธิ์**: PMHQ-Thai (สงวนลิขสิทธิ์ กรมราชทัณฑ์), WHOQOL ฉบับไทย, SCL-90-R ได้มาจากภาคผนวก
คู่มือทางการที่ส่งลงมาให้หน่วยงาน — ใช้ภายในหน่วยงานได้ ห้ามเผยแพร่แบบฟอร์มออกนอกระบบ
(ไม่มีหน้าดาวน์โหลดแบบฟอร์มให้บุคคลภายนอก)

### แบบประเมิน (เพิ่มเติมจาก FAST Model)
- คุณภาพชีวิตผู้ใช้สารเสพติด, SCL-90-R (ระยะแรกรับ), Rosenberg Self-Esteem
- PMHQ-Thai 24 ข้อ (0–3): 0–28 ปกติ / ≥ 29 มีปัญหา → แจ้งสถานพยาบาล
- แบบประเมินพฤติกรรมสมาชิก ทุกสิ้นเดือน 27 ข้อ 10 ด้าน (1–5) รวม 27–135:
  27–63 ต้องปรับปรุง / 64–99 ปานกลาง / 100–135 ดี — กราฟรายเดือน เตือนระดับต้องปรับปรุง
- ความรู้ Matrix (ผ่าน ≥ 70%), ประเมินตนเอง (ข้อความ 3 ข้อ),
  พึงพอใจต่อการบริหาร 6 ข้อ และต่อการบำบัด 30 ข้อ (ค่าเฉลี่ย 1.00–1.80 ... 4.21–5.00)

### รายงานสิ้นสุดรุ่น (ตามแบบกรมฯ)
1 จำนวนสมาชิกชาย/หญิง: เข้า / ไม่จบ (สาเหตุ) / จบอยู่ในเรือนจำ / จบปล่อยตัว / คงเหลือ

## 17. หลักสูตรฟื้นฟูก่อนพ้นโทษ 3 วัน (15 ชม.)
อ้างอิง: คู่มือศูนย์สุขภาพจิต กองบริการทางการแพทย์ กรมราชทัณฑ์ — ไม่ลง บสต. ไม่ติดตาม

### เกณฑ์คัดเลือก

7 จัดการอารมณ์ (โกรธ, รับรู้ความเครียด, ลดความเครียด) / 8 ฟื้นฟูสัมพันธภาพ /
9 สร้างความไว้วางใจ / 10 เคารพคุณค่าในตนเอง / 11 ส่งต่อข้อมูลสุขภาพ / 12 ปัจฉิมนิเทศ
- วิทยากร 1 คนต่อผู้ต้องขัง 50 คน (เตือนเมื่อเกิน)

### แบบประเมิน
- ทบทวนสถานภาพ 11 ด้าน (-10/-5/0/+5/+10): อาชีพ, เพื่อน, ครอบครัว, สัมพันธภาพ,
  ควบคุมตนเองเมื่ออยากยา, เมื่ออยากเหล้า, คุณค่าตนเอง, สุขภาพกาย, สุขภาพจิต,
  ความพึงพอใจทางเพศ, ความพึงพอใจในชีวิต → รวม + กราฟเรดาร์
- รับรู้ความเครียด: อาการ 11 ข้อ ≥ 2 ข้อ → ป้าย "ควรได้รับการลดความเครียด"
- Rosenberg 10 ข้อ (1–4): ข้อ 1,3,4,7,10 ตรง / 2,5,6,8,9 กลับ; 10–20 ต่ำ / 21–30 กลาง / 31–40 สูง
- ความพึงพอใจ 9 ข้อ (1–5): วิทยากร 3 / สถานที่ 4 / ความเข้าใจ 2
  รายงานเป็นจำนวนคนต่อคะแนนต่อข้อ ตรวจผลรวมเท่าจำนวนผู้เข้าร่วม

### ส่งต่อข้อมูลสุขภาพ (กิจกรรม 11) — ข้อมูลอ่อนไหว
- ปัญหาสุขภาพกาย (วัณโรค, HIV, เบาหวาน, ความดัน, โรคติดต่อ, อื่นๆ), สุขภาพจิต,
  แผนรักษาหลังพ้นโทษ, สิทธิการรักษา, รพ. ที่จะรักษาต่อ, ยาที่ต้องเตรียม
- รายการผู้ต้องส่งต่อสำหรับสถานพยาบาล, พิมพ์ใบส่งต่อรายบุคคล
- ไม่เชื่อมกับระบบ HIV

### ขั้นตอนโครงการ 7 ขั้น (เช็คลิสต์ต่อรุ่น)
คัดเลือก → ขออนุมัติโครงการ → ขออนุมัติจัด → เชิญวิทยากร → ดำเนินการ → ประเมินพึงพอใจ → รายงานกรมฯ

### งบเริ่มต้น (แก้ได้ทุกปี)
- วิทยากร 600 บาท/ชม. × 15 ชม. ต่อ 50 คน, วัสดุต่อคน (ตั้งค่า เช่น 20 หรือ 159 บาท), ถัวเฉลี่ยได้
- ใส่จำนวนคนเป้าหมาย → คำนวณงบและจำนวนวิทยากรทันที

## 18. รายงาน

### 18.1 หน้าพิมพ์รายงาน (3 ขั้น)
เลือกระดับ → เลือกตัวกรอง (ปีงบ/หลักสูตร/รุ่น/บุคคล) → ดูตัวอย่าง → พิมพ์ / PDF / Excel
1. รายบุคคล: ประวัติ+รูป, ทุกหลักสูตร, การเข้าร่วม, คะแนน+กราฟ, ความเห็นแพทย์ (ผู้มีสิทธิ์),
   ชุมชนบำบัด (ตำแหน่ง เครื่องมือ วินัย), ใบรับรองการผ่านหลักสูตร
2. รายรุ่น: รายชื่อ+สถานะ, ใบเช็คชื่อ, ตาราง+วิทยากร+ค่าตอบแทน, คะแนนเฉลี่ยก่อน-หลัง
3. รายหลักสูตรในปีงบ: เปรียบเทียบรุ่นต่อรุ่น
4. ภาพรวมทุกหลักสูตรในปีงบ: จำนวนคน (นับคนซ้ำแยก), ค่าตอบแทน, กราฟ, เทียบข้ามปี
5. ค่าตอบแทน / 6. งบประมาณ / 7. บสต. / 8. ผู้ออกจากเรือนจำรายเดือน /
9. ผู้กลับมาต้องโทษซ้ำ / 10. ผู้ผ่านหลายหลักสูตร / 11. การปลดล็อกโดยผู้ดูแล

### 18.2 รายงานประจำสัปดาห์ (อัตโนมัติศุกร์ 15.00)
1 ภาพรวม (รุ่น คน รับใหม่ จบ ออก % เข้าร่วม) 2 กิจกรรมที่ทำตามตาราง (วันที่ หัวข้อ รุ่น ผู้รับผิดชอบ
ผู้เข้าร่วม ผล สรุป) + ที่ไม่ได้ทำพร้อมเหตุผล 3 ผลประเมิน/พฤติกรรม (ตัวเลขรวม ไม่ระบุชื่อ)
4 บสต. + ค่าตอบแทน + งบคงเหลือ 5 ปัญหา/ข้อเสนอแนะ (รวบรวมจากผลกิจกรรม แก้เพิ่มได้) 6 แผนสัปดาห์หน้า
- ผู้ดูแลแก้ไข → "อนุมัติ" → Word/PDF แบบบันทึกข้อความ; ดูย้อนหลัง; รวมเป็นรายเดือนได้

### 18.2A รายงานประจำเดือน และการเสนอผู้บริหาร
- **รายงานประจำเดือน** สร้างอัตโนมัติวันทำการแรกของเดือนถัดไป (รวมจากข้อมูลทั้งเดือน ไม่ใช่แค่แปะรายงานสัปดาห์):
  1 ภาพรวมทุกหลักสูตร (รุ่นที่ดำเนินการ คนเข้า/จบ/ออก + เหตุผล, % เข้าร่วม)
  2 กิจกรรมทั้งเดือนสรุปรายหลักสูตร (จำนวนคาบตามแผน/ทำจริง/ไม่ได้ทำ, ชั่วโมงรวม, วิทยากรภายใน/ภายนอก)
  3 ผลการประเมินเด่นของเดือน (ก่อน-หลังของรุ่นที่จบ, คะแนนพฤติกรรมเฉลี่ยชุมชนบำบัด) — ตัวเลขรวม ไม่ระบุชื่อ
  4 ตัวชี้วัด: บสต. (% ลงครบ/ติดตามครบ), รท.101 (% ลงครบ), ผลงานเทียบเป้าหมายปีงบ (สะสม)
  5 ค่าตอบแทนและงบประมาณ (ใช้เดือนนี้ / สะสม / คงเหลือ)
  6 เหตุการณ์สำคัญ (จากกล่องจดหมายเวรระดับสีแดง/กฎ 5 ข้อ — สรุปจำนวนและการจัดการ ไม่ระบุชื่อ)
  7 ปัญหา อุปสรรค ข้อเสนอแนะ (รวบรวมจากผลกิจกรรมและรายงานสัปดาห์ แก้ไขได้)
  8 แผนเดือนหน้า (รุ่นที่จะเปิด กิจกรรมสำคัญ)
- กราฟประกอบ: แนวโน้มจำนวนคนรายเดือน, % เข้าร่วมรายรุ่น, ตัวชี้วัดเทียบเป้า
- **รายงานไตรมาส/ปีงบ** ใช้โครงเดียวกัน เลือกช่วงเวลาได้

**ขั้นตอนเสนอ (ใช้กับรายงานสัปดาห์และเดือน)**
ร่าง (ระบบสร้าง) → หัวหน้า/รองตรวจแก้ เพิ่มข้อความ → กด "อนุมัติและเสนอ" →
- ล็อกฉบับที่เสนอ (เก็บ PDF + ตัวเลข ณ วันนั้น แก้ไม่ได้ ถ้าต้องแก้ทำ "ฉบับแก้ไข" ใหม่)
- พิมพ์เป็นบันทึกข้อความ (Word/PDF) เรียน ผู้อำนวยการสถานพยาบาล → ผู้บัญชาการเรือนจำกลางเชียงใหม่
  ช่องลงนาม ผู้รายงาน / หัวหน้า / ผอ.สถานพยาบาล (เห็นชอบ) / ผู้บัญชาการ (ทราบ/สั่งการ) ตามสายลงนามหัวข้อ 2.2-0
- ผู้บริหารเปิดอ่านในระบบได้ทันที (หน้า "รายงานที่เสนอ") ระบบบันทึกว่าเปิดอ่านแล้วเมื่อไร
  ผู้บริหารพิมพ์ "ข้อสั่งการ/ความเห็น" สั้นๆ กลับได้ → แจ้งหัวหน้า/รอง (เป็นสิทธิ์เดียวที่ผู้บริหารเขียนได้)
- LINE: แจ้งผู้บริหารว่า "มีรายงานประจำเดือน ... เสนอแล้ว" + สรุปตัวเลขสำคัญ 3–5 บรรทัด (ไม่มีชื่อผู้ต้องขัง)
- คลังรายงานย้อนหลัง ค้นตามเดือน/สัปดาห์/ปีงบ ดาวน์โหลดซ้ำได้

### 18.3 รูปแบบเอกสาร

### 18.4 เอกสารราชการอัตโนมัติ (แก้ก่อนพิมพ์ได้, Word/PDF, แม่แบบแก้ได้)
- บันทึกขออนุมัติโครงการ + ตัวโครงการ, คำสั่งแต่งตั้งคณะทำงาน/คณะวิทยากร
- บันทึกขออนุมัติจัด (ถึงหัวหน้าฝ่าย / ถึงผู้บัญชาการ), รายละเอียดงบ, รายการวัสดุ, รายการถ่ายเอกสาร
- หนังสือเชิญวิทยากรภายนอก, ใบลงทะเบียน/เซ็นชื่อ, เกียรติบัตรทั้งรุ่น
- หนังสือนำส่งรายงาน (เรือนจำกลาง/ทัณฑสถาน และ เรือนจำจังหวัด/อำเภอ)
- แบบรายงานผลการดำเนินงานและการใช้จ่ายงบประมาณของแต่ละหลักสูตร

- ตั้งค่าหน่วยงานครั้งเดียว: ชื่อเรือนจำ ประเภท ที่อยู่ เบอร์ ชื่อ-ตำแหน่งผู้บริหาร เลขที่หนังสือ

## 19. แดชบอร์ด เป้าหมาย ความครบถ้วน ปิดปี

- เป้าหมายคนและรุ่นต่อหลักสูตรต่อปีงบ; แดชบอร์ดผู้บริหาร: ผลงานเทียบเป้า ตัวชี้วัด งบ บสต.
  (สีเขียว/แดงเทียบเป้า) พิมพ์หน้าเดียวได้; สรุปผลประจำปีอัตโนมัติ
- หน้า "ข้อมูลที่ยังไม่ครบ": ไม่มีรูป, ยังไม่ประเมินก่อนเรียน, ไม่บันทึกเกณฑ์รับเข้า, รุ่นยังไม่ปิด
  กดแล้วพาไปกรอก
- ปิดปีงบ: ล็อกข้อมูลปีนั้น (ยกเว้นผู้ดูแล), สำรองแยก, ยกอัตรา/คลังหัวข้อ/เป้าหมายไปปีใหม่

## 20. บันทึกเวร เหตุการณ์ และกล่องจดหมายเวร
- สมุดเหตุการณ์ประจำวัน, รายงานเวร 24 ชม. (ที่อ่านในประชุมเช้า)
- **กล่องจดหมายเวร (Shift Handoff)**: เจ้าหน้าที่เขียนข้อความส่งเวร ระดับ ปกติ / สำคัญ / **สีแดง**
  ผูกกับผู้ต้องขังได้ (เช่น "ฝากติดตามนาย ข. มีอาการซึมเศร้า") ระบุผู้รับ: ผลัดถัดไป / ทุกคน / รายบุคคล
- ผู้รับเข้าระบบ → **ป๊อปอัปบังจอ** แสดงข้อความค้างอ่านทั้งหมด ต้องกด "รับทราบภารกิจ" ทีละข้อ
  - ระดับ **สีแดง**: ยังไม่กดรับทราบ → เข้าเมนูอื่น (เช็คชื่อ ตาราง) ไม่ได้
  - บันทึกว่าใครรับทราบเมื่อไร ผู้ส่งเห็นสถานะ "อ่านแล้ว/ยังไม่อ่าน"
  - เรื่องที่ต้องติดตาม: ผู้รับกด "ดำเนินการแล้ว" + ผล → ปิดเรื่อง; ค้างเกินกำหนดเตือนหัวหน้า/รอง
- **ผู้ใช้กล่องจดหมายเวร**: หัวหน้า/รอง และกลุ่ม A = ใช้ได้เต็ม (ส่ง/รับ/ติดตามเรื่อง)
  กลุ่ม B = ส่งได้ (เช่น พฤติกรรมที่พบในคาบที่ตนสอน) และรับเฉพาะข้อความที่ระบุถึงตนหรือรุ่นที่ตนสอน
  (ไม่เห็นข้อความทั่วไปของเวร) / การเงิน และ ผู้บริหาร = ไม่มีเมนูนี้
- ข้อความส่งเวรที่เกี่ยวกับสุขภาพ เห็นเฉพาะผู้มีสิทธิ์สุขภาพ (คนอื่นเห็นแค่ "มีเรื่องสุขภาพ — ติดต่อพยาบาล")
- ระบบนี้อยู่ในขั้น 2 (ไม่ใช่ขั้นท้าย) เพราะเกี่ยวกับความปลอดภัยของผู้ต้องขัง

## 21. หน้าเลือกงาน (Portal) กับระบบติดตามยาผู้ป่วย HIV
- ระบบ HIV มีอยู่แล้ว แยกโปรแกรมและฐานข้อมูลโดยสมบูรณ์ ห้ามรวม
- หน้าเลือกงานที่ลิงก์หลัก การ์ด 2 ใบ ผ่าน reverse proxy (Caddy) เป็น /rehab และ /hiv
- หน้าเลือกงานไม่ต้องล็อกอิน แต่ละระบบล็อกอินของตัวเอง; เพิ่มการ์ดงานอื่นได้
- ต้องถามเจ้าของก่อนว่าระบบ HIV เดิมทำด้วยอะไร รันที่ไหน

  (บน 2.5 ซม. ซ้าย 3 ซม. ขวา 2 ซม. ล่าง 2 ซม. — ปรับได้), ช่องเส้นจุดกว้างคงที่ ข้อความอยู่บนเส้นจุดนั้น
  ตรวจทุกแบบฟอร์มด้วยการเรนเดอร์ PDF แล้ววางซ้อนภาพต้นฉบับ (overlay โปร่งแสง) ต้องคลาดไม่เกิน 1–2 มม.
  มีหน้า "ปรับตำแหน่งการพิมพ์" (ผู้ดูแล) เลื่อนทั้งหน้า ±มม. เผื่อเครื่องพิมพ์แต่ละเครื่องเยื้อง
- **ฟอนต์เอกสารทุกฉบับ: TH Sarabun New** (เจ้าของดาวน์โหลดไฟล์ฟอนต์ไว้แล้ว)
  ให้เจ้าของวางไฟล์ฟอนต์ (ตัวปกติ ตัวหนา ตัวเอียง ตัวหนาเอียง) ในโฟลเดอร์ `assets/fonts/`
  แล้วฝังฟอนต์ใน PDF จากไฟล์นั้น (ไม่พึ่งฟอนต์ที่ติดตั้งในเครื่อง) ขนาดเนื้อหา 16pt หัวเรื่อง 18–20pt
  ถ้าหาไฟล์ฟอนต์ไม่เจอ ให้หยุดและแจ้งเจ้าของ ห้ามใช้ฟอนต์อื่นแทนโดยไม่บอก
- **ค้นหาภาษาไทย**: ค้นได้ทั้งชื่อ นามสกุล เลขประจำตัว ไม่สนช่องว่าง/คำนำหน้า
- **ความถูกต้องของข้อมูล**: เลขประจำตัวผู้ต้องขัง unique, ตรวจรูปแบบ+check digit เลขบัตรประชาชน,
  unique constraint กันเช็คชื่อซ้ำ/ลงหลักสูตรซ้ำที่ระดับฐานข้อมูลด้วย (ไม่ใช่แค่หน้าจอ)
- **การคำนวณเงิน**: เก็บเป็นสตางค์ (จำนวนเต็ม) ห้ามใช้ทศนิยมลอยตัว
- **ค่าที่แช่แข็ง**: อัตรา ณ วันสอน, เกณฑ์แปลผล ณ วันประเมิน
- **งานตั้งเวลา** (สำรอง, LINE, รายงานสัปดาห์): ถ้าเครื่องปิดตอนถึงเวลา ให้ทำทันทีเมื่อเปิดเครื่อง
  และบันทึกผลทุกครั้ง
- **ประสิทธิภาพ**: index ที่ เลขประจำตัว, เลขบัตร, รุ่น, วันที่; หน้ารายชื่อแบ่งหน้า;
  เป้าหมายทุกหน้าโหลด < 1 วินาทีบน LAN
- **การทดสอบ**: unit test สำหรับกฎสำคัญ (กันลงซ้ำ, คำนวณคะแนน/แปลผล, ค่าตอบแทน, งบ, วันที่ พ.ศ./ปีงบ,
  บันทึกออกจากเรือนจำ), seed ข้อมูลปลอมที่สมจริง (ชื่อไทย 500 คน หลายรุ่น)
- **การอัปเดต**: สำรองก่อน → migration → ทดสอบในสภาพแวดล้อมทดสอบก่อนเสมอ

## 22A. หลักการบันทึกข้อมูลให้เร็วและรายงานได้ง่าย (ใช้กับทุกหน้าจอ)

### บันทึกครั้งเดียว ใช้ได้ทุกที่
- ข้อมูลแต่ละอย่างกรอกที่เดียว ที่อื่นดึงไปใช้ (เช่น เช็คชื่อ → % เข้าร่วม, รายงานสัปดาห์,
  จำนวนผู้เข้าร่วมในผลกิจกรรม, แบบรายงานกรมฯ) ห้ามมีหน้าจอที่ต้องกรอกตัวเลขซ้ำกับที่ระบบมีอยู่แล้ว

### กรอกเร็ว
- ช่องบังคับให้น้อยที่สุดตอนลงทะเบียน (เลขประจำตัว ชื่อ หลักสูตร) ที่เหลือกรอกภายหลังได้
  แล้วไปโผล่ในหน้า "ข้อมูลที่ยังไม่ครบ"
- คัดลอกจาก Excel แล้ววางลงตารางกรอกเร็วได้ทั้งแผ่น (ตรวจก่อนบันทึก)
- ทำกับหลายคนพร้อมกัน: ติ๊กหลายคน → เปลี่ยนสถานะ / ย้ายกลุ่ม / บันทึกผลเดียวกัน
- ค่าเริ่มต้นฉลาด: วันที่ = วันนี้, รุ่น = รุ่นที่ทำงานอยู่, ผู้บันทึก = ตัวเอง
- คีย์ลัด: Ctrl+S บันทึก, Enter ช่องถัดไป, / เปิดค้นหาบุคคล
- ตรวจความถูกต้องทันทีขณะพิมพ์ (ไม่รอกดบันทึก)

### รายงานสะดวก
- นิยามกลาง (data dictionary) ที่ทุกรายงานใช้ร่วมกัน เขียนไว้ในหน้า "คำอธิบายตัวเลข" เช่น
  "จบหลักสูตร" = สถานะครบหลักสูตร, "ผู้เข้ารับการฟื้นฟู" นับรายการลงทะเบียน vs นับคน
  → ตัวเลขทุกรายงานตรงกันเสมอ
- คลิกตัวเลขใดในแดชบอร์ด/รายงาน → เห็นรายชื่อเบื้องหลังตัวเลขนั้น (drill-down)
- "รายงานโปรด": บันทึกชุดตัวกรองที่ใช้บ่อยไว้ กดครั้งเดียวได้รายงาน
- รายงาน ณ วันที่ (as-of): เลือกดูตัวเลข ณ วันใดในอดีตได้ เพื่อให้ตรงกับที่เคยส่งไปแล้ว
- เก็บสำเนารายงานที่ "ส่งแล้ว" (PDF + ตัวเลข) ไว้ในระบบ ดูย้อนหลังได้
- ตรวจความสอดคล้องก่อนออกรายงาน: เข้า = จบ + ไม่จบ + คงเหลือ, งบรวมตรงกับรายการย่อย
  ถ้าไม่ตรงให้เตือนพร้อมบอกจุดที่ผิด
- แบบฟอร์มส่งกรมฯ ออกเป็นรูปแบบเดียวกับต้นฉบับ (ตำแหน่งตาราง หัวข้อ เหมือนเดิม) พร้อมกรอกตัวเลขแล้ว

## 22B. ฟีเจอร์เฉพาะหน้างานในเรือนจำ

### ล็อกหน้าจอด่วน (Quick Lock)
- ปุ่มแม่กุญแจใหญ่มุมบนขวาทุกหน้า + คีย์ลัด Ctrl+L (และกด Esc 2 ครั้งติดกัน)
- กดแล้ว: หน้าจอเบลอทันที → หน้าใส่ PIN/รหัสผ่านของผู้ใช้คนเดิม
  ข้อมูลที่พิมพ์ค้างไว้ไม่หาย ใส่รหัสแล้วทำงานต่อจากจุดเดิม
- ปุ่ม "ไม่ใช่ฉัน" บนหน้าล็อก → กลับหน้าเลือกผู้ใช้ (ข้อมูลร่างบันทึกไว้ให้เจ้าของเดิม)
- ล็อกอัตโนมัติ 15 นาทีใช้กลไกเดียวกัน (ไม่ออกจากระบบทันที ไม่ทิ้งงานที่ค้าง)

### หน้าจอ "คาบของฉัน" (เช็คชื่อ + ผลกิจกรรมในหน้าเดียว)
- กดการ์ดคาบในหน้าแรก → หน้าเดียวมี 2 ส่วน:
  1) เช็คชื่อ (ค่าเริ่มต้น "มา" + รูปย่อ แก้เฉพาะ ขาด/ลา/ป่วย/เหตุราชทัณฑ์)
  2) ผลกิจกรรม (ตามแผน/บางส่วน/ไม่ได้ทำ, การมีส่วนร่วม, สรุป, ข้อเสนอแนะ)
  → ปุ่ม "บันทึกและปิดคาบ" ปุ่มเดียว
- ยังไม่บันทึกหลังจบคาบ → ป้ายแดงค้างในหน้าแรกจนกว่าจะบันทึก
- เมื่อค่าตอบแทนช่วงนั้นถูก "อนุมัติ" → เช็คชื่อและผลกิจกรรมของคาบนั้น **ล็อก**
  แก้ได้เฉพาะหัวหน้า/รองปลดล็อก + เหตุผล + audit log

### บันทึกผลหลังสอน (ทำให้ง่ายที่สุด — เป้าหมาย ≤ 1 นาที, กดอย่างเดียวได้)
หน้า "คาบของฉัน" ส่วนผลกิจกรรม ออกแบบเป็น 3 ขั้น ทำบนแท็บเล็ต/มือถือในห้องได้:
1. **ดำเนินการ**: ปุ่มใหญ่ 3 ปุ่ม — ✅ ตามแผน / ◐ บางส่วน / ✕ ไม่ได้ทำ (ถ้าเลือก 2 ปุ่มหลัง เลือกเหตุผลจากรายการ)
2. **การมีส่วนร่วม**: ปุ่มหน้ายิ้ม 4 ระดับ ดีมาก / ดี / พอใช้ / ควรปรับปรุง
3. **สิ่งที่ได้ (กดเลือก ไม่ต้องพิมพ์)**: ชิปข้อความสำเร็จรูป **ของหัวข้อนั้น** สร้างจาก "จุดประสงค์การเรียนรู้"
   ในคู่มือหลักสูตร เช่น หัวข้อทักษะการปฏิเสธ → [ฝึกบทบาทสมมติครบทุกกลุ่ม] [สมาชิกบอกหลักการปฏิเสธได้]
   [ใช้เวลาเกิน/ไม่พอ] — เลือกได้หลายอัน + ชิปทั่วไป [สมาชิกกล้าแสดงออก] [มีสมาชิกไม่พร้อม/ง่วง]
   [มีเหตุการณ์ต้องแจ้งเวร]
- ช่องข้อความ "สรุปเพิ่มเติม" **ไม่บังคับ** + ปุ่มไมค์พิมพ์ด้วยเสียง (ถ้าเบราว์เซอร์รองรับแบบออฟไลน์)
- ระบบประกอบชิปที่เลือกเป็นประโยคสรุปให้อัตโนมัติ ผู้บันทึกแก้ได้ก่อนบันทึก
- ชิป "มีเหตุการณ์ต้องแจ้งเวร" → เปิดกล่องจดหมายเวรพร้อมเติมรุ่น/คาบให้
- จำนวนผู้เข้าร่วมดึงจากเช็คชื่อ ไม่ต้องกรอก
- หัวหน้า/รองแก้ชิปของแต่ละหัวข้อได้ในคลังหัวข้อ (ระบบเตรียมชุดแรกจากคู่มือทั้ง 3 หลักสูตร)
- ใบ **"บันทึกผลการจัดกิจกรรม"** พิมพ์ได้ต่อคาบ/ต่อวัน: วันที่ เวลา หัวข้อ วิทยากร ผู้เข้าร่วม ผล สรุป
  ช่องลงนามวิทยากร + ผู้บันทึก — ใช้เป็นหลักฐานแนบเบิกค่าตอบแทนและรายงาน

### ผู้รับผิดชอบประจำวัน (Duty Officer)
- ในตารางของรุ่น กำหนด "ผู้รับผิดชอบประจำวัน" ได้วันละ 1 คน (กลุ่ม A) — ค่าเริ่มต้นหมุนเวียนตามรายชื่อ แก้ได้
- ผู้รับผิดชอบประจำวันเห็นการ์ด "คาบวิทยากรภายนอกวันนี้ที่ต้องบันทึกแทน" ในหน้าแรก
- เลยวันแล้วยังไม่บันทึก → ป้ายแดงในหน้าแรกของผู้รับผิดชอบประจำวัน และแจ้งหัวหน้า/รองวันถัดไป
- วิทยากรภายนอกที่อยากเขียนเอง: พิมพ์ใบ "บันทึกหลังสอน" ฉบับสั้น (ติ๊กช่องเหมือนชิป + เขียน 3 บรรทัด)
  ให้เขียนแล้วเซ็น → ผู้รับผิดชอบประจำวันกรอกตาม ระบุ "คัดลอกจากใบบันทึกของวิทยากร" + เก็บใบไว้ที่แฟ้ม

### บันทึกแทนวิทยากรภายนอก (Proxy Entry)
- วิทยากรภายนอกไม่มีบัญชี → เจ้าหน้าที่กลุ่ม A (หรือผู้ได้รับมอบหมาย) กด
  "บันทึกแทนวิทยากรภายนอก" ในคาบนั้น
- เก็บแยกชัดเจน: **ผู้สอน** = วิทยากรภายนอก ก. / **ผู้บันทึก** = เจ้าหน้าที่ ข.
  แสดงทั้งสองชื่อในรายงานและ audit log

### บันทึกพฤติกรรมด่วน (Quick Note)
- ปุ่ม "บันทึกพฤติกรรม" ในหน้าบุคคลและในหน้าเช็คชื่อ (กดที่ชื่อ)
- ข้อความสั้น + วันที่ (ค่าเริ่มต้นวันนี้) + แท็ก **เชิงบวก / เชิงลบ / สังเกต**
  + หมวด (ช่วยเหลือส่วนรวม, ทะเลาะวิวาท, สูบบุหรี่, อารมณ์, อื่นๆ — ตั้งค่าได้)
- แสดงรวมในสมุดส่วนที่ 3 ของเดือนนั้น (ปุ่ม "แทรกสรุป") และให้ที่ปรึกษาเห็นตอนเขียนส่วนที่ 4
- เชิงลบที่รุนแรงแปลงเป็นบันทึกวินัย/เครื่องมือบ้านได้ด้วยปุ่มเดียว

### แยกข้อมูลการต้องโทษรอบเก่าให้ชัด
- หน้าบุคคลแสดงการต้องโทษปัจจุบันเป็นหลัก รอบเก่า **พับเก็บไว้** มีเส้นคั่นชัดเจน
- ทุกข้อมูลจากรอบเก่ามีป้ายแดง "ข้อมูลการต้องโทษรอบก่อน (พ.ศ. ....)"
- คะแนนประเมินรอบเก่า **ไม่ถูกนำมาใช้** เป็นค่าก่อน/หลังของรอบปัจจุบันเด็ดขาด
  เมื่อลงทะเบียนรอบใหม่ ระบบสร้างงานประเมิน Baseline ใหม่ทุกแบบให้อัตโนมัติ
- กราฟแนวโน้มแยกรอบ ไม่ลากเส้นต่อกันข้ามรอบ

### ปฏิทินรวมและตรวจความทับซ้อน
- หน้าปฏิทินใหญ่ รวมทุกหลักสูตรทุกรุ่น (สีตามหลักสูตร) มุมมองวัน/สัปดาห์/เดือน
- ตัวกรอง: หลักสูตร / วิทยากร / สถานที่
- ทะเบียนสถานที่ (ห้องอบรม ลานกิจกรรม ฯลฯ ตั้งค่าได้) ทุกคาบระบุสถานที่
- เตือนอัตโนมัติ: วิทยากรคนเดียวสอน 2 ที่เวลาเดียวกัน / สถานที่เดียวใช้ซ้อนกัน /
  ผู้ต้องขังคนเดียวมีกิจกรรมซ้อน (กรณีอยู่ 2 หลักสูตร)
- แสดงรายการความทับซ้อนทั้งหมดก่อนพิมพ์ตารางแจก

### ชุดกระดาษสำรองฉุกเฉิน (Emergency Offline Kit)
- ปุ่ม "พิมพ์ชุดฉุกเฉิน" → PDF เดียวของกิจกรรม 1–3 วันข้างหน้า (เลือกได้):
  ตารางกิจกรรม, ใบรายชื่อ+รูปย่อ, ใบเช็คชื่อเปล่าทุกคาบ, แบบประเมินเปล่าที่ถึงรอบ (มีชื่อพิมพ์ไว้),
  ใบส่งเวรเปล่า
- เตือนทุกวันศุกร์บ่ายให้พิมพ์ชุดของสัปดาห์หน้า (เก็บแฟ้มไว้ที่ห้องอบรม)
- ไม่มีข้อมูลสุขภาพในชุดฉุกเฉิน
- ระบบกลับมา → กรอกย้อนหลังด้วยโหมดกรอกเร็ว ระบุ "กรอกย้อนหลังจากชุดฉุกเฉิน" ใน audit log

### หลักฐานความยินยอม (PDPA)
- ในขั้นยืนยันการลงทะเบียน: ☑ "ผู้เข้ารับการฟื้นฟูได้ลงนามในเอกสารยินยอมการจัดเก็บข้อมูลแล้ว"
  + วันที่ลงนาม + ผู้รับเอกสาร (เอกสารต้นฉบับเก็บแฟ้ม)
- ยังไม่ติ๊ก → ลงทะเบียนเป็น "ร่าง" ได้ แต่ยืนยันรับเข้าไม่ได้ (ตั้งค่าบังคับ/ไม่บังคับได้)
- พิมพ์แบบฟอร์มยินยอมเปล่าที่มีชื่อพิมพ์ไว้ได้ (ข้อความแบบฟอร์มให้ผู้ดูแลแก้ไขได้
  และควรให้ฝ่ายกฎหมาย/ผู้รับผิดชอบ PDPA ของหน่วยงานตรวจข้อความ)
- กรณีไม่ยินยอม: บันทึกเหตุผล และแจ้งหัวหน้า/รองพิจารณา

### มอบอำนาจอนุมัติชั่วคราว (Out-of-Office Delegation)
- หัวหน้าหรือรองกำหนด "มอบอำนาจอนุมัติ" ให้เจ้าหน้าที่กลุ่ม A 1 คน ระบุวันเริ่ม–สิ้นสุด
  และขอบเขต (อนุมัติค่าตอบแทน / งบประมาณ / อนุมัติคำขอเปลี่ยนตาราง)
- หมดเวลาสิทธิ์คืนอัตโนมัติ, ยกเลิกก่อนกำหนดได้
- ผู้รับมอบอำนาจอนุมัติค่าตอบแทนของตัวเองไม่ได้ (กฎแยกหน้าที่ยังใช้)
- audit log: "เจ้าหน้าที่ ก. อนุมัติแทน (มอบอำนาจโดย หัวหน้า ... ช่วง ...)"
- การกระทำที่ต้องยืนยัน 2 คน (กู้คืน ลบถาวร ฯลฯ) **มอบอำนาจไม่ได้**

## 23. แผนการพัฒนา (ทำทีละขั้น ห้ามข้าม)

**ขั้น 1 — โครงพื้นฐาน + หลักสูตร 12 วัน (ใช้งานจริงได้)**
- โครงโปรเจกต์, Git, .gitignore, README เบื้องต้น, seed ข้อมูลปลอม
- ฐานข้อมูลตามหัวข้อ 5 (ออกแบบรองรับทุกขั้น แต่สร้างหน้าจอเฉพาะขั้นนี้)
- ความปลอดภัยหัวข้อ 2 (ไม่ใช้ OTP), สำรองข้อมูลหัวข้อ 3
- หลักสูตร/รุ่น (เฉพาะ 12 วัน), ทะเบียน + กันลงซ้ำ, นำเข้า Excel, บันทึกออกจากเรือนจำ
- เช็คชื่อ (รวมสถานะเหตุราชทัณฑ์ + รูปย่อ) + โหมดกรอกเร็ว, หน้าแรกตามบทบาท (ส่วนที่เกี่ยวข้อง)
- ล็อกหน้าจอด่วน, หลักฐานความยินยอม PDPA, แยกข้อมูลการต้องโทษรอบเก่า (หัวข้อ 22B)
- แนวทางหน้าตาตามหัวข้อ 4.4 ตั้งแต่ขั้นนี้
- ติดตั้งเป็น Windows Service + HTTPS บน LAN
→ เจ้าของทดสอบกับเจ้าหน้าที่จริง 1 รุ่น (ใช้คู่กับกระดาษ)

**ขั้น 2 — งานหลักของ 12 วัน**
- บสต./รท.101 + ติดตาม + ข้อมูลติดต่อ, คลังแบบประเมิน + แบบของ 12 วัน, ความเห็นสถานพยาบาล
- รายงานรายบุคคล/รายรุ่น, ตรวจความครบถ้วน
- กล่องจดหมายเวร (หัวข้อ 20), บันทึกพฤติกรรมด่วน, ชุดกระดาษสำรองฉุกเฉิน (หัวข้อ 22B)

**ขั้น 3 — ตาราง วิทยากร ค่าตอบแทน งบประมาณ LINE**
- หัวข้อ 11, 12, 13, รายงานประจำสัปดาห์
- หน้าจอ "คาบของฉัน", บันทึกแทนวิทยากรภายนอก, ปฏิทินรวม+ตรวจทับซ้อน,
  ล็อกหลังอนุมัติ, มอบอำนาจอนุมัติชั่วคราว (หัวข้อ 22B)

**ขั้น 4 — หลักสูตร 3 วัน + เอกสารราชการ**
- หัวข้อ 17, 18.4

**ขั้น 5 — ชุมชนบำบัด FAST 6 เดือน**
- หัวข้อ 16 ทั้งหมด

**ขั้น 6 — ภาพรวมและส่วนเสริม**
- แดชบอร์ด เป้าหมาย ปิดปี (19), บันทึกเวร (20), Portal (21), QR เช็คชื่อ

จบแต่ละขั้น: สรุปภาษาไทย + รายการงานทดสอบตามบทบาท + ผลตรวจความปลอดภัย → รอเจ้าของยืนยันก่อนขั้นถัดไป

## 24. เรื่องที่ต้องยืนยันกับเจ้าของก่อนถึงขั้นที่เกี่ยวข้อง
- อัตราค่าตอบแทนจริงและหัวข้อที่เบิกได้ (ขั้น 3)
- ผู้ที่จบหลักสูตรแล้วพ้นโทษระหว่างติดตาม 1 ปี: ติดตามต่อหรือปิด (ขั้น 2)
- หน่วยงานเบิกจ่ายจาก สปสช. หรือไม่ ถ้าใช่ต้องสรุปข้อมูลอะไร (ขั้น 3)
- แบบรายงานประจำเดือน/ไตรมาสที่ต้องส่งกรมฯ (ถ้ามี) (ขั้น 4)
- ระบบ HIV เดิมทำด้วยอะไร รันที่ไหน (ขั้น 6)
- Rosenberg / WHOQOL-26 / SCL-90-R: **ตัดสินแล้ว** ดูหัวข้อ 16B (ภาพแบบฟอร์มจริงอยู่ที่ docs/forms/)
- SCL-90-R: ขอหน้า "วิธีคิดคะแนนรายด้าน" จากคู่มือ FAST เพิ่ม (ภาพที่ได้มามีแต่ข้อคำถาม)
